## 识别与业务统计

先记录每次人为呈现，再核对板上是否产生事件；只统计成功输出的EVENT会漏掉漏检。每个试验至少记录：trial_id、session、card_id、实际数字/非数字、期望工单、开始/移走时间、板上类别、MATCH/WRONG/拒识/无事件、事件序号、判定延迟、照度条件、距离、失败原因和证据文件。

建议初始样本量：十类至少各30次正确料、各30次错误料，另300次空白/字母/部分遮挡/纹理背景。同一标签连续保持不算重复试验。实物类别、字体、手写人和拍摄会话与训练/调参集隔离。

- 有效正确核验率 = 正确工单下产生正确MATCH的次数 / 全部正确工单呈现次数。
- 错料误放行率 = 错误工单下产生MATCH的次数 / 全部错误工单呈现次数。
- 拒识率 = 拒识或在规定等待窗口内无事件的次数 / 全部有效标签呈现次数。
- 重复计数率 = 同一次呈现产生的多余事件数 / 呈现次数。
- 空场/干扰误事件率单列，不能混入大量简单数字样本稀释。

零错误也要报告样本量及置信区间。不要将单帧分类准确率、检测IoU通过率、业务核验成功率混写为同一个“准确率”。

手势为新增实验分支，与数字标签结果分别报告。采集人物ID替代card_id，同一个人和会话不能跨训练/验证/测试；每类、每个人和每种照明都记录。加入空场、非数字姿势、脸/胳膊、衣袖、遮挡和肤色相似背景。现有公开原图验证仅52/148正确接受，尚不达到可靠演示验收；不能只录成功手势，也不能把378个开发负样本零误接受推广到所有背景。两模式共用计数，按EVENT最后的mode筛选，分别实验前可q清零。

## 性能与CPU

NPU的1769238周期只覆盖计算；50 MHz下35.38 ms是纯计算时间。板上另测采集启动→NPU启动、NPU启动→CPU判定、判定→LCD帧提交、三次确认后的业务总延迟。串口事件中的DEC是NPU启动→CPU完成判定，包含这次NPU计算，不是纯CPU开销；正常测量关闭d采集。

使用者已完成CoreMark跑分，保留已有原始日志和测试条件；本轮转换不以重跑为前置条件。下面的独立工程用于需要时复现：

```powershell
python fpga_pg2l100h/vision/build.py --prepare-only --profile coremark --iterations 6000
python fpga_pg2l100h/vision/build.py --profile coremark --iterations 6000 --pds-home D:/PDS/PDS_2022.2-SP6.7-ads-win64
python fpga_pg2l100h/vision/competition/coremark.py --log actual_coremark_uart.txt --output fpga_pg2l100h/vision/validation/coremark_hardware.json
```

CoreMark工程为 `build/coremark_j11/pg2l100h_coremark.pds`，使用相同CPU、50 MHz和片上存储器；固件关闭推理。官方算法固定到EEMBC/CoreMark提交 `1f483d5b8316753a742cbf5590caf5bd0a4e4777`，逐文件校验，移植层与官方算法分离。保留原始完整串口记录，不修改>=10秒判定。6000次是初始配置；若实际运行不足10秒，增加迭代重跑。一次迭代仿真只在测试台提高UART波特率以缩短输出等待，CPU和算法不变；部署固件仍是115200。此短仿真不产生有效成绩。

CoreMark/MHz = iterations × 1e6 / ticks。CoreMark/LUT需明确分母是整个系统还是CPU子模块，并从对应的实际PDS报告提取，不能拿旧Xilinx或MES50HP的资源/跑分代填。当前应用使用片上存储器，未实现指南高阶任务的两路组相联I/D Cache，也未展示板上中断应用；已有BTB/CSR逻辑不等于这些指标均通过验收。

提交PDS综合、布局布线、DRM/APM/LUT/FF占用、最差路径和时序约束结果、位流SHA256；50 MHz设计目标不等于已经时序收敛。CPU波形至少覆盖load-use、转发、分支预测命中/失误和CoreMark关键循环。NPU速度比较需同输入、同INT8算术、同正确输出的CPU基线，未测加速比不填写。
