# 优化轨迹（CHANGELOG）—— 改了什么 / 为什么 / 结果 / 教训

> **这份文档是给"人"看的轨迹**，不是给机器看的日志。它回答三件事：
> 1. **改了什么**（`file:line` + 判据命令，可独立复现）
> 2. **为什么这么改**（当时的证据与推理；含被推翻的推理）
> 3. **结果如何**（实测数字 + 它属于"净赚/净亏/中性"）
>
> **怎么用它学习**：
> - 想知道"现在为什么长这样" → **从下往上读**（每一项都是为了解决上一项暴露出的瓶颈）；
> - 想复现某一条 → 每条的"判据"列给了命令与 CSV 行名；
> - 想避免重犯 → 直接看 **§5 负结果** 与 **§6 方法论教训**（这两节比正面成果更值钱）。
>

> `.fpga-cache/reports/<时间戳>-cm_hw/metrics.json`（每次构建的指标快照）、

## 1. 时间线：正面成果（每项都是"单变量 + 实测"）

> 判据统一为 **绝对吞吐 `CM/MHz × fmax`**（因为各档频率不同，只看 fmax 或只 look IPC 都会骗人）。

### C-2 · 把 load 数据移出前递路径（论文 §III.A 的核心手法）
- **改动**：`hazard_unit.sv:80-96` 新增 `load_use_mem`、`load_use = ex ∪ mem`（load-use 由 1 拍改 2 拍）；
  `core.sv:610-623` 的 `fwd_wb_data` 三个分支全部从**寄存器**出发；`core.sv:236-249/299-303`
  `pc_flush` 优先于停顿；EX 段副作用门控由 `!pipe_stall` 改 `!hold_mem`。
- **为什么**：论文原文 "the data forwarding path becomes the critical path" +
  "we did not include the load data into the forwarding path from the write back stage"。
  我们当时的 top-1 源端是 `u_dmem/mem_reg_0/CLKBWRCLK`（RAMB36 时钟脚）——数据存储器
  通过组合前递环挂在取指地址脚上。
- **结果**：fmax **76.2 → 83.6 MHz**（+9.7%），**LUT 2734 → 2531（−203）**，
  ticks 413,070 → 449,854（**+8.905%**），绝对吞吐 184.4 → 185.8（+0.8%）。
- **判据**：CSV 行 `c2-loaduse2`；盈亏平衡 82.98 MHz，实测 83.6 ⇒ 净赚。
- **最该学的一点**：**代价必须实测**。推理算出的是 +6.917%，实测是 +8.905% ——
  因为 `load_use_mem` 把"距离 2 的消费者"也纳入了停顿，而旧语义下距离 2 完全免费。
  低估 22% 的教训：**"每次多 1 拍"这类推理会漏掉"事件数变了"**。
- **差点漏掉的正确性问题**：2 拍语义破坏了"C-2 之前 `pipe_stall=1` 只可能是 EX 是 load 或硬冻结"
  这条隐含不变量，若不把 EX 副作用门控拆成 `hold_mem` 口径，会**静默丢掉**
  ①load 后距离 2 的 CSR 写 ②EX 里非法指令/ecall 的精确陷阱 ③与 load 无关分支的重定向 ④BTB 更新。

### C-10 · 前递选择改在 ID 段预选
- **改动**：`core.sv:146` 新增 4 位并行 FF `id_ex_fwd_a/b`；`hazard_unit.sv:144-160`
  改判据为"本拍 ID 看到的产生者位置"（下一拍 EX/MEM 的产生者 = 本拍 ID/EX，下一拍 MEM/WB = 本拍 EX/MEM），
  输出 2 位 one-hot；`core.sv:620-623` 前递 mux 的选择端改用寄存器输出。
- **为什么**：C-2 之后的 top-1 源端是 `u_ex_mem/rd_addr_reg[4]`（**地址不是数据**）⇒
  "地址比较"可以在**更早一拍**算好。这正是参照核 ref5 的 V4 配方（"ALU 操作数在 ID 预选"）。
- **结果**：fmax **83.6 → 87.8 MHz**（+5.0%），**ticks 逐位不变**，LUT +123。
- **判据**：CSV 行 `c10-fwdpre`。
- **最该学的一点**：**"把组合链搬到寄存器前面"往往比"把链变短"更有效** ——
  因为瓶颈常常不是逻辑深度，而是"晚到的信号还要穿过一整套选择逻辑"。

### C-11 · 把"分支误判重定向"寄存一拍（切环）
- **改动**：`core.sv:203-208/852-925` 只寄存**分支误判**：`br_redir_eff = redirect && !trap_redir`，
  `br_redir_r <= br_redir_eff`、`br_tgt_r <= actual_target`；`redir_flush = br_redir_eff || br_redir_r`
  冲 ID/EX 与 IF/ID 两拍；**trap/mret 保持组合**（R-01/R48 的不变量不动）。
- **为什么**：C-10 之后 top-1 是**一堵墙**（50 条最差路径同族、Δ(top1,top2)=0.007 ns、route 75.6%）
  ⇒ 按 PITFALLS R47，逻辑重排没有空间，**唯一出路是把环切开**。
- **结果**：fmax **87.8 → 92.6 MHz**（+5.5%），ticks +2.324%，绝对吞吐 195.1 → 201.2（+3.1%）。
- **判据**：CSV 行 `c11-rebuilt-ctl`；重定向冲刷实测 2.00 拍/次。
- **最该学的一点（机器化判据的威力）**：这条改动唯一可能的致命错误是"错路指令提交"，
  所以作者加了一条**每拍检查的断言** `if (!rst && id_ex_valid && (br_redir_r || br_redir_r2)) $error(...)`
  —— 它在**整个回归的每一拍**上检查，0 次触发。**"能否证明没坏"比"跑过没坏"强一个量级。**
- **事故与被销毁后重建**：这份 RTL 曾被 `git checkout` 抹掉（见 §6.10），
  重建后用 `sha256_tree()` 逐位复核与事故前**完全相同**（`a7248c31…`）。

### C-14 · JALR 目标比较改成单链
- **改动**：`core.sv:994` 在 **ID 段**预算 `id_jr_p = if_pred_target - id_imm`；
  EX 段只算 `ex_jr_diff = ex_rs1 - id_ex_jr_p` 并判 `ex_jr_diff[31:1] == 0`。
- **为什么**：原来是"加法器 → 32 位比较器"两条链串联（8 个 CARRY4）。
  把减法挪到 ID（两个操作数在 ID 都是寄存器），EX 只剩 31 位 OR 归约树。
- **结果**：**ticks 逐位不变**（纯结构）；等价性由新增断言（`pred_target[1:0]!=0 ⇒ $error`）钉住。
- **最该学的一点**：`A == B ⟺ (A−B) 的高位为 0` 这类**代数改写**能把"比较链"换成"归约树"，
  代价是加一条断言把"对齐假设"变成机器化判据（不能靠"本来就字对齐"）。

### C-15 · registered flush（让"组合冲刷"整体消失）
- **改动**：误判拍 N 不组合冲 ID/EX；N+1 用寄存器 `br_redir_r` 冲 ID/EX 与 EX/MEM，
  并用它门控错路影子 X0 在 EX 的**全部副作用**（`csr_we/exc_req/irq_take/mret_req/btb_upd_en/redirect_raw/muldiv.op`）。
- **为什么**：C-11 只切掉了尾巴的"PC/取指地址"那一半，链条改挂到**使能端**（`any_redir` fo=122）。
- **结果**：fmax 87.8 → 92.6 档上 **+1.2 MHz**（**远低于预测的 +2.07 ns**）；
  **但族被治好了**：该族 7.791 → 6.795 ns。ticks 逐位不变。
- **最该学的一点（本轮最重要的认知纠正）**：**瓶颈是"族"，不是"某条路径"。**
  治好 top-1 不等于整族消失。这也是本 session **第 3 次"预测收益 >> 实测"**，
  直接催生了工具 `tools/path_families.py`（按族统计，而不是只看 top-1）。

### C-1 · 两级流水 gshare 预测器（BTB 512 / PHT 8192）
- **改动**：`btb.sv` 重写（512 项 + 两级流水口 `p2_pc → q_*`）；新增 `bht.sv`（PHT 8192 项、
  `ram_style="block"` → 1 块 RAMB18）；`core.sv:378-393` 接线；旧 `pred_*` 口保留但恒"不预测"。
- **为什么**：T 拍只用 `pc_next` 当**查表地址**，T+1 拍 `q_*` 已是寄存器输出 ⇒
  BRAM 的 1 拍读延迟被"提前一拍给地址"吸收，**零气泡**。
- **结果**：ticks 460,311 → **453,942（−1.38%）**；误判 11,530 → **8,020（−30.4%）**；
  精度 88.43% → **91.95%**；JAL 误判 1,102 → **190**。
  代价：**LUT +181、FF +91、BRAM +1**。
- **判据**：CSV 行 `deliv117` / `cB-128`；报告 `results/p4-c1-2stage-gshare.md`。
- **最该学的一点**：`q_taken` **刻意不寄存** —— 再打一拍预测就晚于对应的 PC，
  每个 taken 分支多 1 气泡，ticks 必崩。**"哪里不能再打拍"和"哪里必须打拍"同样重要。**

### C-12a · muldiv 操作数直取 rs1/rs2
- **改动**：`core.sv:750-759` 的 `u_muldiv` 例化由 `.a(ex_a)/.b(ex_b)` 改为 `.a(ex_rs1)/.b(ex_rs2)`。
- **为什么**：此时 top-1 正是 `mem_wb/ctrl_reg[wb_src] → u_muldiv/prod_ss_reg/PCIN`，
  操作数经两级 mux 才进 DSP（第二个 LUT6 就是它）。等价性依据：`control_unit.sv:57-98`
  M 扩展走 `OPC_REG` R 型路径 ⇒ 恒有 `ex_a ≡ ex_rs1`、`ex_b ≡ ex_rs2`（逐位等价）。
- **结果**：@131.25 档 WNS **−0.437 → −0.077**，绝对吞吐 273.5 → **286.2（+4.6%）**，
  且 **DSP 输入族从 top-1 消失**。ticks 逐位不变。
- **最该学的一点**：同一个改动**换一个上下文会变号**（见 §5 的 C-12a 负交互），
  所以"上次否掉它"不能直接当结论 —— 必须回测。

### 候选 B · 删掉 C-10/C-14 寄存器块的"清 0 条件"（本轮最大单笔收益）
- **改动**：`core.sv:1140-1152`。原来
  `if (any_redir || id_ex_bubble) 清 FWD_REG; else if (!pipe_stall) 装 fwd_*_pre;`
  ⇒ **EX 重定向组合锥（7×CARRY4）同时进了 D 端 mux 和 CE**。改成 CE 只留 `!pipe_stall`。
- **为什么**：作者用新工具 `tools/path_families.py` 读了 top-50，发现
  **37/50 条路径的终点都是同一个结构**（`id_ex_jr_p_reg/CE` 24 条 + `id_ex_fwd_a_reg[*]_rep/D` 13 条）。
- **结果**：
  - 评分流 @128.125：+0.062 → **+0.090**；原 37/50 条那个族**从 top-50 消失**；
  - **ILA 流 @128.125：−0.434 → +0.000 PASS** ⇒ **交付档从 118.75 提到 128.125 MHz**；
  - ticks **逐位 453,942 不变**（纯时序）。
- **判据**：CSV 行 `cB-128`；上板证据 `results/ila_done.csv` 最后一行。
- **最该学的一点（等价性论证的"干净度"）**：作者先给了一个"顺手修 MRET 潜在 bug"的故事，
  **10 分钟后自己查代码撤回**（`core.sv:1045` 的 `trap_redir` 本就含 `mret_taken`，
  MRET 当拍就冲 ID/EX）。撤回后论证只剩**一条 don't-care 论证**（清 0 生效的四种来源里，
  T+1 进 EX 的槽位永远是气泡或被杀的 X0），**反而更稳**。
  ⇒ **"顺手修了个 bug"式的论证要格外警惕；先查代码事实，再谈机制。**

| `build.tcl` 加 `SYNTH_DIRECTIVE`/`PHYS_OPT_DIRECTIVE` 且**进综合缓存指纹** | 从来没人扫过这两个旋钮；进指纹才能保证"改了策略却命中旧缓存"不发生 |

## 3. 方法论教训（可迁移到任何时序优化工作）

1. **瓶颈是"族"，不是"某条路径"。**
   治好 top-1 不等于整族消失。先看 **top-50 的族分布**：单一大族 ⇒ 值得做结构改动；
   分散 ⇒ 转物理/约束。工具：`python tools\path_families.py`。
2. **同一改动在不同上下文会变号。**
   C-12b' 孤立测 −0.37 ns，在 C-14+C-1 的上下文里 +0.45 ns（值约 6 MHz 达成频率）。
   ⇒ **孤立测量不能用于组合决策**；决策要用"在当前树上的实测值"。
3. **预登记判据把负结果变成干净的科学结论。**
   C-18a 事先写明"若 DSP 数不增而族仍在 PCIN ⇒ 判负回退"，实测 100% 命中 ⇒
   它是一条**结论**，不是一次失败。对比：事后解释容易变成自我辩护。
4. **"能撞上的测试"必须先建模 kill/flush 语义。**
   一条断言"mret 紧邻的消费者要读到前递值"——而那条指令**永远被冲掉**（这正是 MRET 精确性要求）
   ⇒ 它会是一条**永久假警报**，诱导后人去改**本来正确**的 RTL。**比没有测试更糟。**
5. **闸门必须进"判据"，不能只进"提示"。**
   我给 31 位上限加安全余量时第一版只改了提示文本，判据没变 ⇒ 4730 仍被放过。
   "闸门看着在、其实没拦"比没有闸门更危险。
6. **两个流程/配置对比前，必须先对齐所有已知变量。**
   我曾断言"ILA 流比评分流差 0.5 ns = 调试核开销"；对齐策略后实测残差只有 **0.090 ns**
   —— 我把"策略缺失"记成了"调试核开销"。（真正的 ILA 耦合确实存在，但只有周期的 0.7%。）
7. **不要用 shell 正则对 RTL 做文本手术。**
   我用 PowerShell `-Raw` + `-replace` 改时钟，把 `.CLK_HZ` 行与下一行**合并**，
   Vivado 报 `Synth 8-2715`，白跑两个点。改用 Python 并加三条护栏：
   逐处**断言恰好命中 1 次**、`newline=""` 保留换行、替换后**自证三处同源**。
8. **代价必须实测，尤其是"事件数"类。**
   C-2 的代价推理低估 22%，因为漏了"停顿事件数也变了"。
9. **"标签与事实不符"是本工程最危险的一类缺陷。**
   时钟名 `sys_clk_75` 实跑 125 MHz、CSV 表头写着已失效的错公式、
   注释断言"与 XDC 同名(14.286ns)"而实际早已改名 —— 它们不会让任何测试变红，
   但会**误导下一手去改对的地方**。
10. **git 纪律 = 防误删 + 可回退。**
    ① **每改一项就提交**；② 每个验证通过项**立刻 push**；③ **任何回退前先提交或 `git stash`**。
    我本 session 犯了 3 次 git 事故（2 次"提交卷带别人的未提交工作"、1 次
    `git checkout -- core.sv` **销毁了未提交的 C-11**），第③条就是针对第 3 次的。
    另外：网络不通时用 `git bundle create --all` 做**离线全量备份**。
11. **冻结窗口协议。** 三条泳道并行改 RTL 时，任何"用 Vivado 测量"的尝试都会被污染
    （本 session 因此报废了 15 个测量点）。规则：**Lead 说"窗口开放"才允许落盘 `*.sv`**。
12. **环境故障不能被误记成"这一档时序不够"。**
    `IP_Flow 19-3505`（半成品 IP 状态 + 实例重叠）会间歇性让 ILA 建像失败；
    若不先净重建就下"降档"结论，会白白降频。**先分清"环境坏"与"设计不够"。**

## 4. 频率阶梯是怎么选出来的（含非单调性）

约束与工具结果是**非单调**的 —— 目标放低不一定更保险：

| 目标档 | 周期 | 实测 WNS | 达成 fmax | 结论 |
|---|---|---|---|---|
| 131.25 MHz | 7.619 ns | −0.077（候选B前） | 129.9 | 差 0.077，门拒绝 |
| 129.6875 | 7.711 ns | −0.024 | 129.3 | 差 0.024 |
| **128.125** | 7.805 ns | **+0.090** | **129.6** | 交付（候选B后 ILA 流也过门） |
| 125.000 | 8.000 ns | +0.020（旧树） | 125.3 | **比更紧的 128.125 更差** ⇒ 非单调 |
| 118.75 | 8.421 ns | +0.135 | 119.1 | 曾交付过 |
| 105.000 | 9.524 ns | +0.117 | 106.3 | 曾交付过 |

**规律**：收紧约束会让工具更卖力（75→95.45 时 fmax +8.9%），但**过头就崩**，
而且中间会出现"目标更松反而更差"的档位。⇒ **选档只能看"达成值"，不能靠插值预测。**

**时钟配置的三处真源（必须同源，改一处就要改三处）**：
`fpga/top_a100t.sv` 的 `.CLKFBOUT_MULT_F` / `.CLKOUT0_DIVIDE_F` + `fpga/daVinciPro.xdc` 的
`create_generated_clock -multiply_by/-divide_by` + `.CLK_HZ`（给计时器/UART 用）。
本工程用 `tools` 侧的 `sweep_clk.py` 加**断言**改这三处（每处恰好命中 1 次 + 自证同源），
并且**注释里不写数字**（写数字必然随改档而失配 —— 我因此犯过两次）。

## 5. 负结果（**同样重要**：它们省下了大量白工）

| 项 | 预登记判据 | 实测 | 处置 |
|---|---|---|---|
| **C-3** MUL/DIV 出 MEM→EX 前递 | — | 论证：只改 hit/预选锥、不改数据 mux，`ex_mem_fwd_data` 与 ALU 结果同源 | **不做**（论证结案） |
| **C-8** 停顿出取指地址脚 | — | V6 那半已在 C-2 做掉；V7 那半需给 imem 加 `rd_en`，而 R40-2 实测 **−1.5 MHz** | **不做** |
| **C-12c** muldiv 操作数先寄存一拍 | 预期收益大 | ticks **+2.046%**；**FF=1360（=1290+70）= 未被 DSP 吸收**；WNS −0.077→−0.235；墙换族到 `mem_wb/ctrl_reg → id_ex/*_reg/CE` | **回退** |
| **C-18a** ALU_MUL 走单片 DSP（不穿级联） | 若 DSP 数不增而族仍在 `PCIN` ⇒ 判负 | 语义逐位等价（自证断言含 9,711 条乘法 0 触发），但 **DSP48E1 8→8**、39 条仍在 `PCIN`、WNS −0.077→−0.235 | **回退**（判据事先写明，是干净结论） |
| **C-12a** 在 `AlternateRoutability` 下 | — | 默认配置 +0.76%，但 alt 下 **−5.3%** ⇒ **与工具策略强烈负交互** | 换配置后 +4.6%（见 §1），说明"上下文"决定符号 |
| **C-12b'** 孤立测 | — | WNS −0.173 → **−0.543**（Q 侧扇出降了，但每份副本**多一条 CE 引脚**，而当时 top-1 正是 fo=252 的 CE 网）⇒ "**用 CE 换 Q**" | 孤立测判负；但**在 C-14+C-1 上下文里反转为 +0.45 ns** 而保留 |
| **125 MHz 档** | — | 达成 119.6，**比更紧的 131.25 档（128.3）更差** | 非单调，选档看达成值 |
| `phys_opt Explore` @131.25 | — | WNS **−0.465**（基线 −0.077） | 排除（在旧网表上它曾 +1.7 MHz ⇒ **同一旋钮会随网表变号**） |
| `FewerCarryChains` | RVCoreP 的 `main.xpr` 里 `Directive=7` 按 2018.3 枚举即它 | 89.8（基线 92.6） | 排除 |
| `PerformanceOptimized` | — | **Vivado 2018.3 根本没有这个取值**（`-help` 只列 8 个），直接 `[Common 17-161]` | 纠正了我自己的错误假设 |

**负结果的写法要求**（本工程的做法）：把**为什么负**写进**代码注释**（不只写在聊天里），
并注明"在什么条件下会变号"（如 C-12b'）。否则下一手会重犯。
