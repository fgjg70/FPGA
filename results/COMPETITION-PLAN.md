# 紫光赛道一（RISC-V CPU）作战计划 · 2026-10-17

> 三份独立调研发起：规则（docs-sync）、工程化（build-repo）、RTL/软件/测试（shortcom），
> 加上 Lead 亲自核实的赛题原文与器件/裁决事实。**本文是唯一优先级来源**，冲突时以本文为准。

---

## 0. 一句话结论

**赛道已确认：紫光同创杯 · 赛题一「基于 RISC-V 处理器的软硬件系统设计」= 我们现在做的事。**
架构层面我们**已经领先** 2022 年该赛题的大奖作品；**真正的缺口是：①器件必须紫光同创（现在跑在 Artix-7，不合规）②作品形态（无 OS/无 IDE/无视频/无设计报告）③PPA 缺功耗。**
时间：**2026-11-04 18:00 交作品，11-20~22 南京决赛 ⇒ 约 2.5 周**。

---

## 1. 评分模型（拆解自赛题原文 + 往届事实）

| 维度 | 权重感觉 | 我们的现状 | 判定 |
|---|---|---|---|
| **CoreMark 跑分** | 主口径 | 2.1613 CM/MHz（硬件实测，4600 迭代/14 s/328 iter/s，CRC 全对） | ✅ 有正式跑分 |
| **CPU 设计复杂度 / 指令集覆盖** | 高 | 5 级+前递+双预测器(512 BTB+8192 PHT)+精确异常/中断+A 扩展+GEMM | ✅ **强于 2022 大奖**（3 级、无扩展） |
| **PPA** | 中 | 有 LUT/FF/BRAM/DSP/fmax/WNS；**缺功耗** | ⚠️ 补功耗即完整 |
| **紫光同创 FPAG 平台** | **硬门槛** | **Artix-7**（Vivado） | ❌ **最大缺口** |
| **交付物**：工程+设计报告+扩展报告+演示 | **硬门槛** | 有 26 篇实测文档，但**不是"设计报告"体例**；无视频 | ❌ 改写+拍摄 |
| **加分：OS/RTOS** | 加分 | 无 | ❌ 最高性价比 |
| **加分：MicroPython/Arduino** | 加分 | 无 | ❌ 工期长 |
| **加分：自研 IDE/工具链** | 加分（重） | `tools/` 已能编译→烧写→串口回读，只差包装 | ⚠️ 低成本可做 |

**往届水位**：2022 赛题一大奖 = 电子科大（PGL22G、三级流水、CoreMark 5.4，口径存疑）；
2025 紫光杯 926 队报名 / 155 进决赛 / 一等奖 21（≈13.5%）。

## 2. 优先级清单

### P0 —— 不做就无法交付（合规/提交硬门槛）

| # | 事项 | 为什么是 P0 | 工作量 | 建议归属 |
|---|---|---|---|---|
| **P0-1** | **PDS 迁移 + PGL22G 实跑**：MMCM→PLL、XDC→PDC、build 流程 Tcl→PDS、ILA→Pango 调试、BRAM/DSP 资源核对 | 器件不合规 = 一票否决。**好消息：CPU 核零厂商原语，迁移面只有顶层+约束+时钟** | **大（3~5 天）** | 全员 + Lead |
| **P0-2** | **申请/拿到 PGL22G（或紫光同创）板卡 + PDS 软件** | 没有硬件无法实跑；2025 规则允许"自制或第三方紫光同创芯板"，但都要有芯 | 外部依赖（组委会/借用渠道） | 用户 |
| **P0-3** | **补齐 PPA 的功耗**（Vivado report_power / PDS 功耗报告） | 赛题明确要"CoreMark 跑分 + PPA" | 小（0.5 天） | build-repo |
| **P0-4** | **设计报告（30~50 页）**：摘要/系统框图/流水线时序图/PPA 表/CoreMark 截图/上板自启动证据 | 赛题硬性提交物；我们已有 26 篇素材，是**改写合并**而非重写 | 中（2 天） | docs-sync |
| **P0-5** | **演示视频（3~10 分钟）**：断电→上电→14 秒后串口打印 CoreMark+CRC validated；再接 PDS 版实跑 | 硬性提交物；我们已有现成的自启动证据链，拍摄成本低 | 中（1 天） | Lead + 用户 |
| **P0-6** | **修掉 README 的 6 处致命口径矛盾**（同一页 150 MHz 与 106.30 MHz 并存、tick 2.13e9 vs 1.38e9） | 评委第一眼就看 README/报告，自相矛盾直接减分 | **小（0.5 天，最快见效）** | docs-sync |
| **P0-7** | **修正 150 MHz 的越界 Pblock**（`CRITICAL Vivado 12-4433`，`X0Y1:X2Y3` 超出器件） | 交付配置带 CRITICAL 警告不可复现；且**换机极易翻负** | 小（1 次综合 + 重新上板验证） | build-repo |

### P1 —— 直接决定奖项等级（加分 + 得分点）

| # | 事项 | 为什么 | 工作量 | 归属 |
|---|---|---|---|---|
| **P1-1** | **FreeRTOS / RT-Thread Nano 移植** | 赛题头号加分项；**RTOS 前置缺口必须一起补**：WFI 指令、Zicntr(mcycle)、UART RX 中断、trap 兜底 handler、栈溢出检查 | **3~5 天** | sw-verify + shortcom |
| **P1-2** | **把 `tools/` 包装成"自研工具链/IDE"**（GUI 或 VS Code 插件：编译→烧写→串口回读） | 赛题"重"加分项；能力已具备，只差界面 | 2~3 天 | Lead |
| **P1-3** | **指令集/复杂度继续加分**：RV32C（压缩指令，面积/性能双收益）、Zbb/Zbs 位操作、Zicntr、更多 CSR | "支持指令集数 + 设计复杂度"是评分主口径之一 | 中（C 扩展 3~5 天） | rtl-fix + shortcom |
| **P1-4** | **CPU 性能再提**：RAS 复测（C-1 后从未测 fmax，已知 ticks −0.36%）、load-use 距离 2、PDS 下的 fmax 重测 | CoreMark 是主口径；PDS 结果≠Vivado，**迁移后必须重测** | 中 | rtl-bypass + rtl-pred |
| **P1-5** | **RTL 合规补强**：mtvec 向量模式、load/store access fault、mtval 带地址、指令地址非对齐异常 | 评委问"RV32IM 完整吗"要能答；也是 RTOS/生态的地基 | 中（2~3 天） | rtl-fix |
| **P1-6** | **修正 RTL 缺口**（shortcom 33 条里的 P1）：UART 无背压/FIFO、MMIO 忽略 wstrb、mtime 非原子、GEMM 未完成 | "工程规范/设计完整性"得分点 | 中 | sw-verify |

## 3. 两周作战计划（按周粒度）

### 第 1 周（10/18–10/24）：**合规 + 报告骨架**
- D1–D2：**拿到 PDS + 板卡**（用户）；Lead 写迁移清单；docs-sync 开始压设计报告。
- D2–D5：**P0-1 PDS 迁移**（顶层/约束/时钟/构建）→ 首次 PDS 综合 → 频率/资源实测。
- D3：**P0-3 功耗**（Vivado 先出，PDS 后补）。
- D4–D6：**P0-6 修 README 矛盾 + P0-7 修 Pblock** + 重上板验证。
- D7：**P1-1 RTOS 前置缺口**（WFI/Zicntr/UART RX 中断/trap handler）开工。

### 第 2 周（10/25–10/31）：**加分 + 作品形态**
- D8–D11：**RTOS 移植完成**并跑通（最大加分）。
- D9–D12：**P1-2 IDE 包装** + **P1-3 指令集扩展**（选一个：C 或 Zb*）。
- D12–D14：**P0-4 报告定稿 + P0-5 视频拍摄**（含 PDS 实跑画面）。

### 最后 3 天（11/1–11/3）：**收口**
- 全量回归 + PDS 复现 + 报告/视频/源码打包 + 提交预检（11/4 18:00 截止）。

## 4. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| **PDS 迁移后频率大幅下降**（40nm Logos vs 28nm Artix-7） | CoreMark 跑分下降 | 提前在 PDS 下重跑族分析；必要时降频交付 + 用 CM/MHz（架构效率）讲故事 |
| **PGL22G 装不下**（3116 LUT/1502 FF/9 BRAM/8 DSP vs ~22K LUT） | 无法上板 | 迁移前先跑 PDS 综合看资源；必要时裁 GEMM/降低预测器规模 |
| **板卡/软件借不到**（11/4 截止） | 合规失败 | 立即联系组委会/小眼睛科技；备选"自购第三方紫光同创芯板" |
| 2026 赛题一原文未检索到 | 可能要求变化 | 进官方群要《2026 紫光选题指南》原文核对 |
| "CoreMark 5.4"口径存疑（单发射顺序核物理上不可能） | 对标失真 | 三种口径都备数字（CM/MHz 2.1613 / 328 iter/s / 4600 迭代 14 s） |
