# FLASH 烧写证据（2026-10-17）

## 烧的是什么
| 项 | 值 |
|---|---|
| 镜像 | `fpga/cpu_a100t_spix4.bit`（**150 MHz**, WNS **+0.007**, UART 已验证） |
| 转换后 | `fpga/cpu_a100t_spix4.bin`（3,825,788 字节） |
| 闪存 | **mt25ql128**（128 Mb QSPI，Mfg ID `20` / Type `ba` / Capacity `18`） |
| 接口 | **SPIx4**（`CONFIG_MODE SPIx4` + `BITSTREAM.CONFIG.SPI_BUSWIDTH 4` + `CONFIGRATE 50`） |
| 电压/配置 | `CFGBVS VCCO`，`CONFIG_VOLTAGE 3.3`，`UNUSEDPIN PULLUP` |

## 为什么必须读回（本工程 PITFALLS R44 的血泪记录）
`program_hw_cfgmem` 在 `PROGRAM.VERIFY=0` + `CFG_PROGRAM=0` 时**仍会打印**
`[Labtoolstcl 44-377] Flash programming completed successfully` ——
所以**工具的成功字样不是证据**；这里用的是**16 MB 读回 + 逐字节 diff**（`VERIFY=PASS`）。

另外两个已绕过的坑：
- `27-3347 Failure to set flash parameters` 的真因不是 part 不匹配，而是 **SPI flash accessor 设计没被加载**；
  本工具在第 1 步显式加载 `spi_xc7a100t_pullup.bit`（x4 镜像用 pullup 变体，与 `UNUSEDPIN PULLUP` 对应）。
- `write_cfgmem` 拒绝从 header 写 1 的 bitstream 造 SPIx4 镜像（`[Writecfgmem 68-20]`）⇒
  构建时必须带 `SPI_BOOT_X4=1`（本工程 `build.tcl` 已支持）。
