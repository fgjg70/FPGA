### ⛔ 明确不做（有数据支撑，不要再讨论）

| 项 | 否决依据 |
|---|---|
| **C 扩展（压缩指令）** | ① 评分三项**零收益**（CoreMark 用 `-march=rv32im` 编译，二进制里没有压缩指令）② 要**重写整个前端**（变长取指、`pc+2/+4`、压缩展开）③ LUT 增加、布线压力加剧 ④ **风险等级是 #2 的十倍** |
| **双发射** | ① CPI 仅 **1.099**，可用 ILP 富余只有 ~10%（其余周期已在停顿）② **route 已占 66%**，复制发射资源（regfile 双读口×2 / ALU×2 / 前递网络×2）→ **fmax 几乎必然下降** ③ 净效果对三项指标可能为负 |
| **Cache（2 路组相联）** | `dmem` 已是单周期命中 BRAM；`imem` 是 **0 拍组合 ROM** —— 两者都不需要 Cache 掩盖延迟。见 `results/p7-cache-analysis.md`（**该文有一处需更正**：原文称"imem 也已是 BRAM"，实际 imem 是组合 LUT ROM）|
| **RAS / gshare** | 实测净亏，已留痕并保留复现开关 |
| **A 扩展作为性能手段** | A 与双发射**无关**：A 服务**多线程/多核同步正确性**，双发射服务**单线程 ILP**。本项目是单 hart 裸机、无同步需求 → A 的定位只是"功能完备性边角料" |

> **排序说明**：#2 之所以排第一，因为它是**唯一能同时改善两项指标**的改动
> （LUT 大降 → CoreMark/LUTs +40%；取指链拆短 → 可能提 fmax），
> 且它正是 C/双发射的前置条件（先解布线，才谈得上扩展前端）。
> #1 排在 #2 之前只是因为**成本为零**，且它的结果决定 #8 是否值得做。

## 工程纪律（已固化）

判据与工具不再靠人盯:

```bat
cmd /c tools\doctor.bat                          REM 环境自检 + R1 漂移检测
python tools\fpga_workflow.py verify             REM 增量回归, 期望 8 PASS
```
