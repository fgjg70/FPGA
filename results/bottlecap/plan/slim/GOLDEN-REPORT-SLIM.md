## 6. 待确认假设（按 CONTRACT 最保守解释实现）

1. ReLU: 本模型 78 个 conv 中 73 个后接普通 ReLU(其余 5 个 linear)。CONTRACT §5 的leaky flag 只提供 0.1 斜率或 linear, 没有 slope=0 选项; 本方案用 per-tensor 非对称量化 [min=0, zp=-128] 的 int8 底部饱和实现精确 ReLU(requant 后 +zp_out 时负值饱和到 -128, 反量化=0)。RTL v0.8 新增 NN_F_RELU 后两种实现等价(负支直接归零),本脚本的整数 golden 已按 CONTRACT 公式逐位实现; 不改任何 RTL/公式, 只改校准域选择。
2. ADD_R 的 KADD: CONTRACT §12.3 要求 R<=u16。本模型 20 个 add 实测 ratio=s_s/s_d ∈ [0.179, 1.59] -> R ∈ [5875, 52108] <= 65535, 与 CONTRACT/quant_lib 的 KADD 选择一致;脚本仍内置'R<=65535 才取 K=15'的 u16 保护(未来 ratio>2 时按合同约束重选 K)。
3. concat: 3 个源张量 + 目标张量共享同一 per-tensor (s,zp)(int8 精确 copy 的硬约束, quant_lib.build_groups 对 copy 做 union)。目标张量 56x56x216=677,376 B。
4. 4x nearest upsample: 模型 concat 里 p4(14x14)->56x56 是 4x, 引擎只有 2x; 展开成两次2x(2 的幂下与 4x nearest 逐元素相同), 并对重复的 14->28 上采样做 CSE(省 1 op)。
5. upsample 通道偏移: 引擎 UP2X + dst 通道偏移要求 ic8==oc8, 故 concat 用的上采样先独立上采样到同通道临时张量, 再 copy 到目标张量通道偏移(与 sim/prog/yolo 既有口径一致)。
6. 残差 add 的写回方向: type A(F.relu(x+conv2)) 写回 x 张量(relu 域)使底部饱和=ReLU; type B(InvertedResidual 的 x+conv, 无 ReLU) 写回卷积分支(线性域); type C(FPN 两个relu 域操作数之和) 写回其一。三种都满足 ADD_R 公式, 不改硬件。type B 的目标域是'卷积输出 ∪ 和'的并集, 会牺牲一点卷积分支精度(本模型实测 E2E 仍很高, 见 GOLDEN-REPORT)。
7. 校准集: tools/bottlecap/data/test 中固定 seed 抽样 32 张(只用测试集, 与训练集无关)。
8. 输入量化: 1x3xHxW float[-1,1] -> PACKED3 int8, conv0 的 IC_pad=8 权重后 5 个 ic 为 0。
9. 层内激活只有 ReLU(无 ReLU6/LeakyReLU): plan 每个 op 显式 act='relu'/'none', 并在 flags bit4(v0.8 RELU)置位; leaky flag 恒 0。
