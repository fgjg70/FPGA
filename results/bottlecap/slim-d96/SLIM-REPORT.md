## 3. 为什么不是 160×160 / width_multiplier=0.5

现 NPU 的 A 缓冲是**单张量 96KB** 上限；`SlimMobileNetV2Backbone` 的 `stage2.0.block.0`（1×1 扩通道）在 `S/2` 分辨率上输出 32 通道，因此单张量激活峰值为 `(S/2)^2 × 32` 字节：

| 输入 | 该张量字节 | 96KB 上限 (98,304 B) | 判定 |
|---|---|---|---|
| 96×96 | 73,728 B | 98,304 B | PASS |
| 112×112 | 100,352 B | 98,304 B | FAIL |
| 128×128 | 131,072 B | 98,304 B | FAIL |
| 160×160 | 204,800 B | 98,304 B | FAIL |
| 176×176 | 247,808 B | 98,304 B | FAIL |

即：**160×160 用现有拓扑不可行**（峰值 204,800 B = 上限的 208%），128 也不行。另外 width_multiplier=0.5 时 `stage5.1` 的 inverted-residual 隐层达到 320 通道，超过描述符硬限制 IC/OC≤256（CONTRACT §4），所以 width 必须 ≤0.4（c5=64 → 隐层峰值 256，正好合法）。下面是 6 组候选配置 × 3 种输入的完整对照：

**备选（未实施）**：输入 112×112 + `stage2[0] InvertedResidual expansion 4->3 (hidden 32->24)` ⇒ **架构本身不成立**：FPN 使用 F.interpolate(scale_factor=2.0)，要求输入能被 32 整除；112 的 stage 尺寸 [56, 28, 14, 7, 3] 上采样后与 C4 不一致。
该方案需要改一行架构（expansion 3），会让 checkpoint 无法再用原类直接重建、转换器也要跟着改；因此仅在 96 精度不足时才值得考虑，本版不实施。

**备选（未实施）**：输入 128×128 + `stage2[0] InvertedResidual expansion 4->3 (hidden 32->24)` ⇒ A 峰值 98,304 B（96.0 KB）、W 106,352 B、op 71，容量仍 FAIL。即使扩到 128，`stage1` 的 64×64×16 张量做 3×3 dwconv 时输入+输出并发需要 131,072 B，超过 A+B 的可用摆放，所以本拓扑下 96 已是现 NPU 容量上限。
该方案需要改一行架构（expansion 3），会让 checkpoint 无法再用原类直接重建、转换器也要跟着改；因此仅在 96 精度不足时才值得考虑，本版不实施。

> 上述 112/128 的结论是**脚本实测**而不是推断：112 在 fx shape-prop 阶段就因 `add_8` 的 7 vs 8 尺寸不匹配而失败（脚本捕获后按“架构不可行”记录）；128 通过临时把 `InvertedResidual` 默认 expansion 改成 3 实际构造模型并跑 A/B 摆放仿真得到 A 峰值 98,304 B / B 摆放失败。因此本拓扑+现 NPU 容量下的输入上限就是 96。

## 7. 部署注意事项

1. 摄像头 320×240 先缩放到 **96×72**，再上下各补 **12** 行边缘像素到 96×96，像素 `/127.5-1`；输入 conv0 用 PACKED3（3 B/像素，CPU 生成）。
2. 三个 head 输出在 24×24 网格上解码：3×3 local peaks → confidence Top-40 → class-aware NMS(0.35) → Top-4；在 MCU 侧完成，与 `decode_multi_predictions` 完全一致。
3. 坐标还原：框 ×95 得到 letterbox 像素坐标，减 pad_top，再按 ×320/96、×240/72 映射回 320×240。
4. 权重（BN 折叠后）按 CONTRACT §6 的 `[tap][IC_pad][OC_pad]` / depthwise `[tap][OC_pad]` 排布；Q 区每层 `6*OC_pad+16` 字节，共 22,608 B。
5. 全部通道为 8 的倍数；IC/OC 均 ≤256，可直接用现 RTL 的 conv/dwconv/upsample/add 描述符，无需改 RTL、无需 DDR3。

## 8. 模型重建命令（converter 直接照抄）

```python
import torch
from nut_detector.mobilenet_anchor_free_slim import SlimMobileNetNutAnchorFree

ckpt = torch.load("results/bottlecap/slim/best_model.pt", map_location="cpu",
                    weights_only=False)
cfg = {k: ckpt["config"][k] for k in ("num_classes", "width_multiplier", "fpn_channels")}
model = SlimMobileNetNutAnchorFree(**cfg)   # num_classes=4, width_multiplier=0.4, fpn_channels=64
model.load_state_dict(ckpt["model"])        # strict=True 可过
model.eval()
x = torch.zeros(1, 3, 96, 96)               # 部署输入 96x96（96x72 内容 + 上下各 12 行 edge pad）
objectness, class_logits, box_logits = model(x)   # [1,1,24,24] / [1,4,24,24] / [1,4,24,24]
```
