# 四色瓶盖多目标检测模型训练过程

## 1. 任务目标

该模型用于在一张 `320×240` 摄像头图像中同时检测 1～4 个瓶盖，并输出每个目标的类别、置信度以及左上角和右下角坐标。

类别编号如下：

| 类别编号 | 英文名称 | 中文名称 |
| --- | --- | --- |
| 1 | `red_cap` | 红色瓶盖 |
| 2 | `purple_cap` | 紫色瓶盖 |
| 3 | `green_cap` | 绿色瓶盖 |
| 4 | `yellow_cap` | 黄色瓶盖 |

模型与坚果、电子器件、日常货物模型分别保存，彼此没有覆盖。

## 2. 原始数据整理

原始数据目录为 `瓶盖数据集`，共 200 张真实拍摄图片，图像尺寸全部为 `320×240`。

由于文件编号存在少量跳号，程序先按文件名中的数字进行升序排序，再按照排序后的位置划分类别：

- 第 1～50 张：红色瓶盖。
- 第 51～100 张：紫色瓶盖。
- 第 101～150 张：绿色瓶盖。
- 第 151～200 张：黄色瓶盖。

每种颜色都包含打光和不打光的真实照片。

## 3. 自动提取目标与生成基础标签

数据准备程序首先根据固定背景与瓶盖之间的颜色、亮度和局部残差信号生成前景掩膜，然后进行开运算、闭运算、膨胀和孔洞填充，获得每张真实图片中的瓶盖轮廓。

根据轮廓生成：

- 瓶盖透明裁片和 alpha 掩膜。
- 原图坐标系中的检测框 `(x_min, y_min, x_max, y_max)`。
- 去除瓶盖后的背景图，用于后续合成。

坐标系保持为左上角原点，x 轴向右、y 轴向下。

全部 200 张真实图的检测框均通过可视化检查，未发现将大面积灯光区域误认为目标的情况。

## 4. 防止训练/测试数据泄漏

不是先增强再随机划分，而是先隔离真实源图：

- 每个类别 44 张真实图仅用于生成训练集，共 176 张。
- 每个类别 6 张真实图仅用于生成测试集，共 24 张。
- 测试源图按照亮度排序，从最暗到最亮均匀抽取，以覆盖明暗环境。

训练集和测试集不会使用同一个真实瓶盖裁片或同一个真实背景源。

## 5. 多目标数据增强与合成

最终生成：

- 训练集：3500 张、8750 个目标。
- 测试集：500 张、1250 个目标。
- 训练集与测试集图片数量比例严格为 7:1。
- 1、2、3、4 个目标的训练图片各 875 张。
- 1、2、3、4 个目标的测试图片各 125 张。
- 各类别目标数量最多只相差 1 个，这是因为目标总数不能被 4 整除。

同一张图允许出现相同颜色或不同颜色的瓶盖。目标之间保留至少约 6 像素间隔，不生成互相重叠的目标。

目标级增强包括：

- `0°～360°` 随机旋转。
- `0.78～1.24` 倍随机缩放。
- 亮度 `0.82～1.18` 倍。
- 对比度 `0.88～1.14` 倍。
- 轻微色温变化，避免破坏瓶盖的基本颜色语义。
- 对透明边缘进行轻微羽化，使裁片与背景自然融合。

整图级光照增强随机选择以下七个层次：

- `neutral`：中性光照。
- `dim`：偏暗环境。
- `bright`：强打光环境。
- `warm`：偏暖环境。
- `cool`：偏冷环境。
- `low_contrast`：低对比度环境。
- `transition`：明暗和色温连续过渡环境。

此外还随机加入轻微暗角、相机噪声和小幅高斯模糊。增强操作在离线生成数据集时完成；本次正式训练直接读取已经生成的固定图片与标签，没有再次叠加在线增强。

## 6. 标签格式

每张图片旁边都有同名 TXT 标签文件，每行表示一个目标：

```text
class_id x_min y_min x_max y_max
```

例如：

```text
1 42 36 97 91
4 180 112 239 171
```

数据集还提供：

- `train_annotations.csv` 和 `test_annotations.csv`。
- `train_coco.json` 和 `test_coco.json`。
- `source_split.csv`，记录真实源图的训练/测试归属。
- `summary.json`，记录图片、目标、类别和光照层次统计。

## 7. 输入预处理

摄像头输入为 `320×240 RGB`：

1. 保持宽高比缩放为 `224×168`。
2. 上下各补 28 像素，使输入成为 `224×224`；补充区域使用相邻边缘像素，不补黑边。
3. 坐标按照相同缩放和补边关系转换。
4. 像素按照 `pixel / 127.5 - 1` 归一化到 `[-1, 1]`。
5. 张量排列为 `NCHW`，输入形状为 `[1, 3, 224, 224]`。

解码完成后，再将检测框坐标还原到原始 `320×240` 坐标系。

## 8. 网络结构

模型名称为 `enhanced_mobilenetv2_fpn_decoupled_head`，参数量为 2,048,721。

### 8.1 骨干网络

骨干采用 NPU 友好的增强 MobileNetV2：

- 使用深度可分离卷积和 Inverted Residual 模块。
- `backbone_width = 0.55`。
- 从输入中提取四层特征：`C2=56×56`、`C3=28×28`、`C4=14×14`、`C5=7×7`。

### 8.2 特征金字塔

- 从 C5 自顶向下逐级上采样并与 C4、C3、C2 横向融合。
- 每层使用残差卷积块进一步提取特征。
- FPN 通道数为 72。
- 将 P2、上采样后的 P3 和 P4 拼接，在 `56×56` 分辨率形成最终融合特征。

### 8.3 Anchor-free 解耦检测头

融合特征分别进入三个独立分支：

- Objectness 分支：3 层卷积，输出 `[1,1,56,56]`。
- Classification 分支：3 层卷积，输出 `[1,4,56,56]`。
- Box 分支：2 层卷积，输出 `[1,4,56,56]`。

解码时在 56×56 网格上选择候选目标，经过 NMS 后最多保留 4 个检测结果。

## 9. 迁移学习策略

没有从随机参数开始训练，而是加载日常货物模型：

```text
runs/daily_goods/enhanced_daily_goods_detector_2m_transfer/best_model.pt
```

该预训练模型已经学会通用的背景、物体轮廓、瓶盖形状、目标存在性和检测框定位能力。

迁移时复用了：

- MobileNetV2 骨干参数。
- FPN 和多尺度融合参数。
- Objectness 分支参数。
- Box 定位分支参数。
- 分类卷积塔中的通用特征参数。

由于原模型的四个类别语义与四色瓶盖不同，只跳过并重新初始化：

```text
class_head.weight
class_head.bias
```

前 3 个 epoch 冻结骨干网络，仅训练 FPN 与检测头；第 4 个 epoch 开始解冻全部参数进行端到端微调。本次没有使用知识蒸馏，`distill_weight = 0`。

## 10. 损失函数

总损失为：

```text
Loss = 2.0 × HeatmapLoss
     + 2.0 × CenterConfidenceLoss
     + 1.5 × ClassificationLoss
     + 5.0 × BoxSmoothL1Loss
     + 2.0 × IoULoss
```

- HeatmapLoss：CenterNet 风格 focal heatmap loss，正样本项额外乘以 4，增强目标存在性学习。
- CenterConfidenceLoss：直接约束真实目标中心的 objectness，减少有物体但 obj 偏低的问题。
- ClassificationLoss：带 `0.02` label smoothing 的交叉熵。
- BoxSmoothL1Loss：`beta=0.03` 的 Smooth L1。
- IoULoss：`1 - IoU`，直接优化框的重合程度。

每轮测试后的模型选择分数为：

```text
score = F1 + MeanIoU + 0.10 × MeanObjectness
```

连续 8 个 epoch 未改善时自动早停，因此训练在第 21 个 epoch 结束，保留第 13 个 epoch 的最佳权重。

## 12. 测试结果

测试集包含 500 张图片和 1250 个目标。

| 指标 | 结果 |
| --- | --- |
| True Positive | 1250 |
| False Positive | 0 |
| False Negative | 0 |
| Precision | 1.000 |
| Recall | 1.000 |
| F1 | 1.000 |
| Mean IoU | 0.9696 |
| 目标数量准确率 | 1.000 |
| 整图完全正确率 | 1.000 |

红、紫、绿、黄四类以及 1～4 个目标的各分组测试均达到 Precision=1.0、Recall=1.0。

这些指标来自与训练源图隔离的增强测试集。部署前仍应使用新拍摄、未参与任何合成的真实多瓶盖图片进行最终独立验证。

## 13. ONNX 导出与验证

部署文件为：

```text
bottle_cap_color_detector_2m.onnx
```

- ONNX 文件大小：约 7.80 MiB。
- 输入：`[1,3,224,224]`。
- 输出：objectness、class logits、box raw 三个张量。
- ONNX checker：通过。
- ONNX Runtime 推理：通过。
- PyTorch 与 ONNX 最大原始输出误差：`4.2915×10⁻⁶`，低于 `1×10⁻⁴` 验证阈值。

## 14. 复现命令

以下命令在解压后的包根目录执行。正式数据集与模型已经包含在包内，不需要重新生成；这些命令用于复现流程。

### 14.1 重新生成到一个新目录

```powershell
python prepare_bottle_cap_multi_dataset.py `
  --output-dir bottle_cap_color_dataset_rebuilt `
  --train-count 3500 `
  --test-count 500
```

### 14.2 迁移训练

```powershell
python -m nut_detector.train_enhanced_multi `
  --dataset-dir bottle_cap_color_dataset_multi_augmented_7to1 `
  --output-dir runs/bottle_cap_colors/reproduced `
  --epochs 32 `
  --batch-size 32 `
  --num-workers 4 `
  --learning-rate 0.0004 `
  --fpn-channels 72 `
  --backbone-width 0.55 `
  --transfer-checkpoint runs/daily_goods/enhanced_daily_goods_detector_2m_transfer/best_model.pt `
  --reset-class-head `
  --freeze-backbone-epochs 3 `
  --patience 8 `
  --class-names red_cap purple_cap green_cap yellow_cap `
  --domain bottle_cap_colors
```

### 14.3 详细测试

```powershell
python -m nut_detector.evaluate_multi_mobilenet_anchor_free `
  --checkpoint runs/bottle_cap_colors/reproduced/best_model.pt `
  --dataset-dir bottle_cap_color_dataset_multi_augmented_7to1 `
  --output-dir runs/bottle_cap_colors/reproduced/evaluation
```

### 14.4 导出 ONNX

```powershell
python -m nut_detector.export_mobilenet_anchor_free `
  --checkpoint runs/bottle_cap_colors/reproduced/best_model.pt `
  --output-dir runs/bottle_cap_colors/reproduced `
  --output-name bottle_cap_color_detector_2m.onnx
```
