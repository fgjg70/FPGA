## 1. 生命周期与复现命令

```powershell
python tools/yolo/download_assets.py            # cfg+weights（尺寸校验）
python tools/yolo/convert_yolo_fastest.py       # ① 浮点落地 + 全证据
python tools/yolo/quantize.py --hw 128 --augment-calib 9   # ② int8 PTQ
python tools/yolo/golden.py --hw 128             # ③ 全整数 golden 位精确自检
python tools/yolo/make_vectors.py --hw 128      # ④ plan/model/wq/checksums/代表层向量
python tools/yolo/evaluate.py --hw 320 --augment 9         # ⑤ float vs int8 框匹配
python tools/yolo/gen_report.py                 # 本报告
```

全链确定性：输入图为公式 `q[y][x][c] = int8((x*13 + y*7 + c*29 + seed) & 0xFF)`（seed=12345）；权重/校准/量化无随机数。重复运行 `plan.json`/`checksums.txt`/`yolo_wq.hex` 逐字节一致。

## 2. 模型结构与权重读取（①）

- cfg：131 个 layer（84 conv 中 **28 depthwise**，18 shortcut，3 maxpool，5 route，18 dropout，2 yolo）；输入 3×320×320 训练分辨率。
- 官方 `.weights` 的**前 20 B 是 AlexeyAB darknet 头**（3×int32 + uint64 seen），去掉后 346062 floats 与 cfg 逐层参数个数（含 BN 的 bias/scales/mean/var）**精确相等**。这是本任务最容易错的一步，`load_weights()` 内置字节数 assert，任何偏移都会直接 fail。
- 数值抽查（layer 0/2）：权重 std 0.527/1.135、absmax 1.788/4.534；BN gamma 0.83~4.17、所有 BN 层 var>0。
- BN 折叠：`W'=W·γ/√(var+ε)`、`b'=β-mean·γ/√(var+ε)`（官方权重里 BN 层的 conv bias 即 β，注意 darknet 对 BN 层不再训练单独 conv bias，实测文件里就是这样）。

## 4. 存储/激活预算 vs CONTRACT

### 4.1 权重与量化参数（与分辨率无关）

| 项 | 字节 | CONTRACT 预算 | 余量 |
|---|---:|---:|---:|
| W 区 int8（§6，OC/IC 均 pad 到 8）| **319,792** | 320 KB = 327,680 | 7,888 |
| Q 区 payload（§7 v0.3.1，84 层 packed）| **44,256** | 48 KB = 49,152 | 4,896 |
| WQ 平面（yolo_wq.hex）| **376,832**（92,208 行×32b）| 368 KB | 0（铺满，补 0）|

Q 区每层载荷布局（**T-accel 必须按此读 Q**，v0.3.1；`qoff` 由 plan.json 给出、16B 对齐）：
```
qoff + 0                    : bias_adj[OC_pad]  int32 × OC_pad
qoff + 4*OC_pad             : M_pos[OC_pad]     int16 × OC_pad
qoff + 6*OC_pad             : tail 16 B = [zp_out, zp_in, leaky_en, SHIFT, 12×0] (int8)
每层字节数 = 6*OC_pad + 16； 84 层合计 44,256 B
```

### 4.2 激活缓冲 A/B（每分辨率实测，来自分配器）

| 输入 | A 峰值 | B 峰值 | 并发峰值 | 最大单张量 | 输入 packed | 可行性（A=96KB,B=32KB@x60000/x78000）|
|---|---:|---:|---:|---:|---:|---|
| 320 | 307200 | 0 | 307200 | 614400 | 307200 | 不可行（op 0 tensor 1 (204800 B) does not fit A/B） |
| 160 | 76800 | 0 | 76800 | 153600 | 76800 | 不可行（op 0 tensor 1 (51200 B) does not fit A/B） |
| 128 | 98304 | 32768 | 131072 | 98304 | 49152 | **可行** |
| 96 | 69120 | 18432 | 73728 | 55296 | 27648 | **可行** |

**关键发现（需同步 CONTRACT §3）**：v0.3.1 原计划 A=0x60000(64KB)/B=0x70000(64KB) **放不下 128 输入**：layer 9 的输出张量（24ch@64×64）单张量就有 **98,304 B**，超出 64 KB；且该张量与残差支路输入 32,768 B 同时活跃，需要 128 KB 总活跃量。

实测可行切分（**仍恰好占满 512 KB 窗口，BRAM36 数量与 64K+64K 相同**）：
```
WQ : 0x00000 .. 0x49E10  (W 319,792 B)  + Q 0x50000..0x5ACE0 (44,256 B)  <= 368 KB
A  : 0x60000 .. 0x78000  (64+32 = 96 KB)   <- 输入 packed 3B/像素 @A+0
B  : 0x78000 .. 0x80000  (32 KB)
NN_BYTES 不变 = 512 KB；BRAM36: WQ 92 + A 24 + B 8 = 124 + 核心 9 = 133/135（与 Lead 的预算一致）
```
`plan.json` / `model.json` 已按 `a_base=0x60000, b_base=0x78000` 生成；**建议 CONTRACT §3 改为此切分**（仅移动 A/B 边界，不改窗口大小）。

⚠ **当前 `nn_pkg.sv` 仍是 `NN_A_OFF=0x60000 (64KB)` / `NN_B_OFF=0x70000 (64KB)`**：该布局下 **128 输入不可部署**（单张量 98,304 B > 64KB），但 **96 输入可行**（实测分配 peak A=55,296 B / peak B=18,432 B）。若 Lead 暂不改 nn_pkg，可用 `make_vectors.py --hw 96` 生成 96 输入向量；改 nn_pkg 后当前 128 plan.json 可直接用（src/dst 是 buf 相对偏移，与基址无关，只需 A/B 容量一致）。

## 5. int8 PTQ（②）与 golden（③）

### 5.1 量化契约实现（CONTRACT v0.3.1 §5）

- 权重 per-OC 对称：`s_w[oc]=max|W'[oc]|/127`，`w_q=clamp(round(W'/s_w),-127,127)`；
- 激活 per-tensor 非对称：`s_a=(max-min)/255`，**`zp_a = -128 - round(min/s_a)`**（Lead 确认口径；[0,1] 图像 ⇒ `s_in=1/255, zp_in=-128, a_q=round(a·255)-128`）；
- 累加：`acc = Σ a_q·w_q + bias_adj`，int64；`bias_adj=round(b'/(s_a_in·s_w)) - zp_in·Σw_q`；
- requant：`M_pos=round(s_a_in·s_w/s_a_out·2^SHIFT)`；`M_neg=(M_pos·3277+16384)>>15`（引擎现算，Q 区不存 M_neg）；`y=(acc>=0?acc·M_pos:acc·M_neg)>>SHIFT`（**floor**）；`out=clamp(y+zp_out)`；
- **每层独立 SHIFT**（tail[3]，16..24）：取使 M_pos 落在 int16 内的最大 SHIFT，实测 SHIFT 直方图见下表；M_pos 范围 174..32,754（全模型），整数舍入误差 <1e-3；
- conv 边界外像素填 **zp_in**（不是 0），padding 通道权重量 0；激活 padding 通道填 `zp_a`；checksum 只覆盖真实通道；
- 残差 add：两个操作数在同一激活组，强制 **zp=0 对称量化**（硬件 raw int8 saturating add 精确）；
- 池化/上采样/route-concat：同组共享 (s_a, zp_a)，raw int8 拷贝/取 max。

## 6. 端到端精度（⑤）与未达标项分析

评测集：真实图片 + **确定性增广**（本机网络受限，GitHub raw 大量连接重置，只稳定抓到少量真实图；`evaluate.py --augment 9` 对首图生成 9 个确定性变体（镜像/裁剪/亮度/缩放），case 名 `#augK` 标注，报告如实区分）。float 与 int8 用**完全相同**的 letterbox(填0.5)、decode、NMS(0.45)、阈值(0.25)。

| 输入 | float 框数 | int8 框数 | 匹配(IoU≥0.5) | 匹配率 | mean IoU |
|---|---:|---:|---:|---:|---:|
| 320 | 43 | 74 | 37 | **86.1%** | 0.867 |
| 160 | 58 | 70 | 49 | **84.5%** | 0.812 |
| 128 | 54 | 62 | 44 | **81.5%** | 0.799 |
| 96 | 18 | 24 | 14 | **77.8%** | 0.825 |

float 基线（同集，dog.jpg@320）：dog 0.625 / bicycle 0.594 / car 0.499、0.396。

**未达标**：CONTRACT/任务要求 int8 逐层 cos≥0.99 且端到端框匹配率≥90%；实测都未达到。根因（已用独立实验定位）：
1. **18 个 residual-add 链路把 branch conv 输出与 sum/identity 绑在同一 (s_a,zp_a)**（CONTRACT §11 要求 raw int8 add 两操作数 scale/zp 相同）。sum 的动态范围由 identity 主导（例：branch 输出范围 ±1.5，同组 sum 范围 ±19），branch 输出实际只用到 ~20 个量化台阶，单层 cos 掉到 0.93~0.96；这是逐层 cos 不达标的最大单项（约 45/91 个失败层与 add 组绑定有关）。
2. **per-tensor 激活量化**（契约固定）对 leaky 重尾分布偏保守：M_pos 整数格点、requant floor 偏置、输出 scale 由极值决定，误差沿 ~50 层链式累积。
3. 校准集只有 1 张真实图（+9 个确定性增广）；更多真实图可改善 320 下 80%→90% 量级的匹配率，但不改变 (1) 的结构性损失。

**可选修复（需 Lead/T-accel 决策，未实施）**：给 add op 增加一个 per-tensor 源 requant 标量 `R=round(s_src/s_dst·2^SHIFT)`（tail 里加 2B），branch conv 用**自己的**非对称 scale，add 做 `dst=clamp(dst + round(src·R/2^SHIFT))`，即消除 (1)。改动面：add op 的 Q 读取 + 1 个 int8×int16 乘法；预期逐层 cos 可回到 ≥0.99 且端到端匹配率显著提高。另一选项：shortcut add 改由 CPU 软件执行（route/concat 已是 CPU），完全不占引擎。

## 7. 建议输入分辨率

**建议 128×128**（给 Lead 拍板的依据）：

- **容量**：128 是唯一能塞进 512 KB 窗口并保留完整 int8 权重/Q 的方案：W 312.3 KB + Q 43.2 KB + A 96 KB + B 32 KB；A/B 峰值恰好 128 KB。
- 160/320 **不可行**（按 §8 紧凑布局）：输入 packed 分别 76,800/307,200 B，最大单张量 153,600/614,400 B，超出 A/B 容量（A 96 KB，B 32 KB）；即使扩到 64K+64K 也不够（98,304 B 单张量 >64 KB 已卡死 128）。
- MACs：128 → 20.07 M（相对 320 的 125.44 M 只有 16%），96 → 11.29 M 但检测能力明显变差（float 基线 10 case 只有 2 个框，128 有 12 个）。
- 端到端：128 的 float 检测仍可用（dog 类在 128 上也检出，见 eval 明细）；320 的 float 精度最好（4 框/图）但装不下。
