## 1. 应用场景已落地（赛题"应用场景构建"）

`sw/nn_demo.c`：用 GEMM 搭一个神经网络推理核心。

**为什么选 GEMM**：神经网络推理里耗时占比**绝对主导**的就是矩阵乘
（全连接层就是它；卷积也可 im2col 化归为它）。它同时满足三个条件：
(a) 计算密集且可量化 (b) 结果可逐元素校验 (c) 有明确的"软件 vs 加速"对比基准。

| 项 | 值 |
|---|---|
| `gemm_cycles` | **196,264** |
| `macs` | 4,096 |
| `cycles_per_mac` | **47.91** |
| `checksum` | `0x9d5de1c5` |

| `mismatch`（逐元素比对）| **0** |

> 校验和与主机端 Python 独立计算的结果**完全一致**，这是这个基线的可信依据。
> 注意 `checksum_ref` 必须是**独立累加器 + 独立乘法路径** —— 第一版我错写成
> "再对 C 求一次校验和"，于是两者恒等、`match` 永远是 1，一个**永远为真、

## 2. 硬件加速单元：设计

### 2.1 接口（存储器映射寄存器）

| 偏移 | 名称 | 访问 | 说明 |
|---|---|---|---|
| `0x00` | CTRL | W | bit0 = start（自清），bit1 = irq_en |
| `0x00` | STATUS | R | bit0 = busy，bit1 = done（读时清） |
| `0x08` | A_ADDR | W/R | 矩阵 A 基址（byte） |
| `0x0C` | B_ADDR | W/R | 矩阵 B 基址 |
| `0x10` | C_ADDR | W/R | 矩阵 C 基址（int32） |
| `0x14` | M | W/R | A 的行数 |
| `0x18` | K | W/R | A 的列数 = B 的行数 |
| `0x1C` | N | W/R | B 的列数 |
| `0x20` | CYCLES | R | 本次运算周期数（软件直接算加速比） |

### 2.2 运算语义

`C = A × B`，int8 输入、int32 累加。
`A[i][k] = A_BASE + i*K + k`（行主序）；`B[k][j] = B_BASE + k*N + j`；
`C[i][j] = C_BASE + (i*N + j)*4`。

### 2.3 **阻塞点：访存通路**（这是必须先解决的设计问题）

本核 `dmem` 只有**一个读口**，且被 CPU 的 LSU 独占：

- 加速单元若直接读 `dmem`，就必须与 CPU 争用同一个读口；
- 每拍一次读意味着**每个元素都要一拍**，并行度上不去；
- 结果写回还需要一个写口（`dmem` 是单口）。

**三条可选路线**（按改动量排序）：

| 路线 | 做法 | 代价 | 评价 |
|---|---|---|---|
| **A. 本地缓冲**（推荐先做） | 加速单元自带 A/B/C 的片上缓冲，CPU 用 MMIO 把数据推进去、算完再读出来 | 需要软件搬运数据，搬运开销要算进加速比；但**零访存冲突**，好验证 | ✅ **首选**。实现自包含、可独立验证、不动 CPU/存储子系统，风险最低 |
| B. 共享 dmem + 仲裁 | 加一个仲裁器，CPU 停止时让给加速单元 | 要给 CPU 加 stall 通路；单口限制使加速单元每拍只能取一个操作数，**并行度受限于访存带宽** | 中等改动，但收益被单口卡住 |
| C. 加双口 dmem | 改成真双口 BRAM | 面积/时序代价大；且 BRAM 行为级推断出双口需要重构 dmem | 收益最大但风险最高，放在最后 |

**路线 A 的具体形态**（下轮直接照这个实现）：

```
gemm_accel.sv
  ├─ 参数寄存器 (CTRL/STATUS/M/K/N/CYCLES + A/B/C 基址用作本地缓冲的窗口)
  ├─ 本地 A_buf[256]  (int8)  ── CPU 按字写: MMIO_WDATA 写到 A_WIN + off
  ├─ 本地 B_buf[256]  (int8)
  ├─ 本地 C_buf[256]  (int32) ── CPU 按字读: A_WIN/C_WIN + off
  ├─ 运算: 单周期完成一个输出元素的全部 K 次乘加 (用 K 个 DSP 并行),
  │        或按 4/8 路并行、多拍完成 (面积/时序折中)
  └─ 完成 -> 置 done + 可选中断 (复用 mip.MTIP 之外的软中断, 或简单轮询)
```

**并行度的账**：`M=K=N=16` 共 4096 MAC。若
- 1 MAC/拍 → ≥4096 拍 → 相对软件 196k 拍约 **48×**
- 16 MAC/拍（一次算完一整行）→ 约 256 拍 → 约 **766×**

而软件侧还要加"把数据搬进本地缓冲"的开销（16×16 int8 = 256 字节 = 64 次字写；
C 读出 256 字 = 256 次读）。即使算上搬运，**加速比仍在几十倍量级**，
足以作为"AI 模型性能"的量化证据。

### 2.4 正确性验证方式（与基线同一套判据）

1. 软件先用**同一个不变量**（`sw/nn_demo.c` 的初始化公式）生成 A/B；
2. 软件把 A/B 搬进加速单元本地缓冲，启动，轮询 done，读回 C；
3. 与**已有的独立参考实现**（`checksum_ref` / `count_mismatch`）逐元素比对；
4. 打印 `gemm_cycles`（软件路径）与 `accel_cycles`（加速单元自报），
   算加速比 —— 两个数都来自硬件计数器，可比。
