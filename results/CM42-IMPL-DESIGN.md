## 0. 一个必须修正的认识：load-use 的消费者主要是"分支"

我原来的假设是"load 后面跟的是算术运算，所以加一个后级 ALU 就能消化"。实测把这个假设打掉了。

`tools/dual_issue_potential.py` 对 `-O2` 的 CoreMark 窗口做了 load-use 消费者画像 `[实测]`：

| 消费者类型 | 次数 | 占比 |
|---|---:|---:|
| **BR / JMP（分支/跳转）** | **24,412** | **59.1%** |
| ALU / MUL | 9,775 | 23.7% |
| LOAD（load 套 load） | 7,049 | 17.1% |
| STORE | 93 | 0.2% |
| 合计事件 | 41,329 | 100% |

按距离拆：

| 距离 | BR | ALU | LOAD | 说明 |
|---|---:|---:|---:|---|
| 1 | **13,531** | 968 | 5,688 | 紧邻，最多 |
| 2 | 3,427 | 1,534 | 1,142 | |
| 3 | **7,149** | 715 | 8 | |
| 4 | 0 | 52 | 209 | MUL 2,916 |
| ≥5 | 305 | 350 | 0 | |

**为什么是分支？** CoreMark 的链表与矩阵循环：
```c
while (list) { ...; list = list->next; }   // load 出的指针, 下一轮循环条件是分支
```
`list = list->next` 是 load，紧接着的 `while(list)` 是分支 —— **load→branch 是 CoreMark 的主导模式**。

### 0.1 这个数据推翻了什么

| 原假设 | 实测 | 后果 |
|---|---|---|
| 后级 ALU 主要消化"ALU 消费者" | 只有 23.7% 是 ALU | 双 ALU 直接收益只有 1/4 |
| 分支与 load 无关 | **59.1% 的 load-use 消费者是分支** | 任何"把分支判定推后"的方案都会**放大**惩罚 |
| C-2 的 2 拍停顿是"保守" | 对 load→branch 而言，**2 拍是必要的**（要拿到数据才能判定方向） | 不能简单地"停得更少" |

**⇒ 结论：真正的出路不是"让 ALU 晚点算"，而是"让分支不必等数据"。**

## 1. 设计原理：从"停等"改成"猜后验证"

### 1.1 两种范式的本质区别

| | C-2（现行） | 本方案 |
|---|---|---|
| load 数据未就绪 | **冻结流水线 2 拍** | **照常往前跑**，按预测方向执行 |
| 分支依赖 load | 必须等数据 → 停 2 拍 | **按预测方向先跑**，数据到了再验证 |
| 何时发现猜错 | 不猜，所以不会错 | E2 段验证，错了才重定向 |
| 代价 | 每次 load-use 2 拍 | **每次误判多 3 拍**（惩罚从 2 涨到 5） |

**核心交换**：用"误判惩罚变大"换"load-use 停顿归零"。

在 `-O2` 上算这笔账 `[推算]`：

```
load-use 停顿       = 59,742 拍  (总停顿 76,987 的 77.6%)
重定向停顿          = 11,500 拍  (8,020 次 × 1.43 拍)
其余(muldiv 等)     =  5,745 拍
------------------------------------------------
新方案: load-use 归零                        -59,742
        误判惩罚 1.43 → 5 拍 (+3.57)
        8,020 次 × 3.57                      +28,631
------------------------------------------------
净变化                                       -31,111 拍
```

**单发射就先赚 31,111 拍（−8.4%）。** 这是双发射之外白拿的一份。

### 1.2 为什么必须两个 ALU

"猜后验证"要求同一条指令**可能被算两次**：

- **E1 算一次**：操作数齐 → 直接出结果；不齐（依赖刚 load 的值）→ 结果作废但**不阻断流水**。
- **E2 再算一次**：此时 load 数据已从 dmem 回来，操作数齐 → 得到正确结果。

所以每条执行通路需要 **E1 和 E2 各一个 ALU**。双发射下就是 **4 个 ALU**（2 早 + 2 晚），
这正是 SweRV EH1 的配置。

> **注意区分**：SweRV 的第二个 ALU 在 EX4（9 级），我们放在 E2（7 级）。位置不同但原理相同：
> **在 load 数据可达的那个时间点，再摆一个能算的单元。**

## 2. 目标架构：7 级双发射

```
F1 → F2 → D → E1 → M → E2 → W
```

| 级 | 职责 | 关键信号 | 相对现结构的来源 |
|---|---|---|---|
| **F1** | PC 生成 + BTB/PHT 查表地址 | `pc`, `p2_pc`, `btb_q_*` | 现 IF 段的 pc + btb |
| **F2** | **64 位取指**（BRAM 寄存读）+ 指令打包 | `imem_rdata[63:0]`, `pkg_lo/hi` | 现 imem 输出寄存器 |
| **D** | 双译码 + **发射判定** + regfile 读 + 生成指令束 | `ctrl_a/b`, `rs*_a/b`, `issue_ok` | 现 ID 段（扩双份） |
| **E1** | **ALU #1 ×2**：地址计算 / 普通运算 / 初判分支 | `e1_res[0:1]`, `e1_ok`（操作数齐否） | 现 EX 段 |
| **M** | LSU（非对齐拆分 / AMO）+ dmem 访问 | `lsu_*`, `dmem_rdata` | 现 MEM 段 |
| **E2** | **ALU #2 ×2**：用 load 数据重算 / **分支最终验证** | `e2_res[0:1]`, `br_verify` | **新增** |
| **W** | 双写口写回 | `wb_data[0:1]` | 现 WB 段 |

### 2.1 为什么是 7 级而不是 6 级

要放下"E1 → M → E2"这个结构，M 必须夹在两个 ALU 之间（load 数据在 M 末尾返回，E2 才能用）。
再加上 F1/F2 两级取指（64 位 BRAM 读必须寄存一拍），自然就是 7 级。

**6 级做不到**：如果 E1 和 E2 相邻（E1→E2），load 数据在 M 段才回来，E2 用不上 —— 双 ALU 就白装了。

### 2.2 每级的关键契约

| 契约 | 内容 | 违反了会怎样 |
|---|---|---|
| 取指相位 | `imem_rdata(N) == mem[pc(N)]`，取指地址 = `pc_next` | 与现有 `imem` 配对不变式一致，不能改 |
| 分支判定 | D 段**按预测**发方向；E1 若能判则判；E2 强制验证 | 若只信 E1，load→branch 会判错 |
| 重定向 | 统一在 E2 末发出，冲刷 F1/F2/D/E1/M（**5 拍**） | 惩罚计算与验收都要按 5 拍 |
| 写回 | E2 末 → W 段写两个口 | 双写冲突需仲裁（见 §4） |

## 3. 关键机制："猜后验证"怎么实现

### 3.1 一条指令的两种命运

每进入 E1 的指令带一个 **`opnd_ready`** 标志（D 段算出来的）：

```systemverilog
// D 段: 操作数是否在进入 E1 时就已就绪
opnd_ready = !(依赖前一条 load 且该 load 尚未写回)
```

| `opnd_ready` | E1 做什么 | E2 做什么 |
|---|---|---|
| 1（正常） | **算出正确结果**，`e1_result_valid=1` | 透传，不做运算 |
| 0（等 load） | **不阻断流水**，结果标记为无效 | 用 dmem 回来的数据 **重算**，结果有效 |

**注意 E1 不是"随便算一下"**：它在操作数不齐时必须**不产生副作用**（不写寄存器、不写内存、
不触发异常、不更新 BTB）。这条约束比"算错"更危险 —— 见 §7 风险 R1。

### 3.2 分支的处理（本方案的核心）

```systemverilog
// E1: 操作数齐 → 立即判定, 与预测比对
if (opnd_ready && is_branch) begin
    e1_taken = branch_unit(rs1, rs2, br_type);
    e1_mispredict = (e1_taken != pred_taken) || (e1_taken && target != pred_target);
end

// E2: 强制验证 (无论 E1 是否判过)
//   操作数不齐的指令在这里拿到真值; 操作数齐的指令这里只是重复一次校验
e2_taken = branch_unit(rs1_e2, rs2_e2, br_type_e2);
br_verify = (e2_taken != pred_taken_e2) || ...
```

- **操作数齐**：E1 就发现误判，立即重定向（惩罚 3 拍：F1/F2/D/E1）。
- **操作数不齐**：E1 不断言，E2 才发现（惩罚 5 拍）。
- **为什么 E2 还要再算一次**：E1 若因操作数不齐而"没判"，E2 是唯一判定点；
  若 E1 已判，E2 的重算是**冗余但安全**的（可用来交叉校验，仿真时可断言两者一致）。

### 3.3 重定向的优先级（沿用现有纪律）

| 事件 | 何时生效 | 惩罚 |
|---|---|---|
| 陷阱 / mret | 检出当拍（组合） | — |
| 分支误判（E1 发现） | E1 末 | 3 拍 |
| 分支误判（E2 发现） | E2 末 | **5 拍** |
| 非对齐访存拆分 | M 段冻结 | 1 拍 |
| muldiv busy | 冻结 | 按除法步数 |

**关键**：E1 和 E2 可能同时报告误判。**E1 优先**（更老的指令），E2 的报告丢弃。
这条必须有断言守护。

## 4. 双发射的发射规则与依赖检查

### 4.1 规则（起手版）

| 指令类型 | slot0 | slot1 |
|---|:--:|:--:|
| ALU / LUI / AUIPC | ✓ | ✓ |
| BR / JAL | ✓ | ✓ |
| JALR | ✓ | ✗ |
| LOAD / STORE | ✓ | ✗（单 LSU） |
| MUL | ✓ | ✓ |
| DIV / AMO / CSR | ✓ | ✗ |

同时发射的条件：① 两条在同一 64 位取指包内；② 无 RAW/WAW；③ 不争用同一功能单元；
④ slot0 不是 taken 分支（否则 slot1 白发射 —— 但**允许发**，只是不计入吞吐统计）。

> 实测配对率：此规则下 `-O2` 为 **27.6%**（允许跨包 + BR 进 slot1）。见 `CM42-ROUTES.md` §7.2。

### 4.2 依赖检查的实现（关键路径要点）

```
RAW:  (slot0.rd == slot1.rs1) || (slot0.rd == slot1.rs2)   // 5 位 × 2 比较
WAW:  (slot0.rd == slot1.rd)                                // 5 位 × 1 比较
排除: rd == 0
```

**这是 D 段最长的组合链**（3 个 5 位比较 + 归约）。按 `C-10` 的经验，它应当：
- 用 `(* max_fanout = 16 *)` 约束输出；
- 如果它成为新 top-1，就把"发射判定"再拆一级（D1/D2 → 8 级），或用**预译码前瞻**
  （F2 段就开始算 rs1/rs2，D 段只做比较）。

## 5. register file：4 读 2 写

### 5.1 三个候选

| 方案 | 资源 | 读延迟 | 风险 |
|---|---|---|---|
| **A. `RAM16X1D` 分布式 RAM**（biRISC-V 同款） | 约 32~64 LUT | 组合（0 拍） | 低。**推荐起手** |
| B. BRAM 真双端口 ×2 块 | 2 × RAMB36 | **1 拍**（需提前给地址） | 中：要在 F2 预译码 rs 字段 |
| C. 触发器阵列 + mux | 1024 FF + 大量 mux | 0 拍 | **高**：Verbeure 明确指出 FPGA 上会撞布线墙 |

**起手选 A**，代码可直接参考 biRISC-V 的 `biriscv_xilinx_2r1w.v`（`SUPPORT_REGFILE_XILINX=1` 分支）。
它同时处理了两条指令写同一寄存器的冲突与 x0 恒零。

### 5.2 双写口冲突

两条指令同拍写同一寄存器 → **只保留 slot1（更新的那条）**，用优先 mux 实现。
RISC-V 的 WAW 已被 §4.2 的检查拦住（不允许配对），所以这种情况只在**独立发射**时出现，
但保险起见仍要仲裁。

## 6. 关键路径预算（这是方案成败的关键）

### 6.1 现状基线

| 项 | 值 |
|---|---:|
| 5 级 @150 MHz | 每级 **6.667 ns** |
| route 占比 | 65~76% |
| 当前 top-1 | `imem` 输出 → 译码 → load-use → 停顿 → 取指地址 |

### 6.2 7 级后的预算分配

目标 **100 MHz ⇒ 10 ns/级**。7 级给了比现在**多 50%** 的时间预算，这是空间所在。

| 级 | 主要逻辑 | 预算 | 备注 |
|---|---|---:|---|
| F1 | PC mux + BTB 地址 | 10 ns | 比现在宽松（现 PC 环最紧） |
| F2 | BRAM 读 | 10 ns | BRAM 存取本身 <3 ns，余量大 |
| D | 双译码 + 依赖检查 + regfile 读 | **10 ns** | 最紧的一级，见 §4.2 |
| E1 | 2×ALU（无前递 mux） | 10 ns | 前递选择已在 D 段预选（C-10 手法） |
| M | LSU + dmem | 10 ns | 现 MEM 段 |
| E2 | 2×ALU + 分支比较 + 重定向 | **10 ns** | 次紧，重定向要早出 |
| W | 写回 mux + regfile 写 | 10 ns | 很轻松 |

**关键判断**：把现在的 5 级摊到 7 级，每级逻辑量约为原来的 **0.71 倍**，
而时间预算是原来的 **1.5 倍**（150→100 MHz）。**这就是"用级数换频率"的全部数学。**

即使双发射让 D/E1/E2 三级的逻辑翻倍（×2），`0.71 × 2 = 1.42`，仍小于 1.5 —— **理论上够**。
但布线拥塞会吃掉余量，所以要靠 §7 的物理约束。

## 7. 物理实现约束（按"用面积换走线"的范式）

| # | 约束 | 具体做法 | 依据 |
|---|---|---|---|
| P-1 | **强制局部化** | 用 Pblock 把 core 绑在单一区域（现在 `X0Y1:X2Y4`，面积翻倍后需重扫） | LUT 只用 4.9%，**没有理由摊开** |
| P-2 | **ALU 复制体相邻** | 两套 ALU 必须落在同一 Pblock 内，且靠近 regfile | 它们之间有密集连线 |
| P-3 | **BRAM 与消费者对齐** | imem/dmem 的 BRAM 列要和 core 的 Pblock 对齐 | ref5 教训：BRAM 4→8 块，**LUT 只 +4，fmax −18.68 MHz** |
| P-4 | **扇出封顶** | `redirect` / `actual_taken` / `issue_ok` 加 `(* max_fanout = 16 *)` | 实测 `actual_taken` 扇出 60 时单跳 0.947 ns |
| P-5 | **imem 扩容与流水重构同批做** | 16 KB → 24 KB 与 7 级改造一次完成 | 扩容自带 −5~10 MHz 布线代价，别付两遍 |
| P-6 | **不要摊平流水寄存器** | 双发射让流水寄存器翻倍（约 +800 FF），必须紧凑放置 | FF 只用 1.1%，成本可忽略 |

## 8. 实施顺序（每步都必须可独立验收）

| 步 | 内容 | 验收判据 | 回退点 |
|---|---|---|---|
| **S0** | `-O2` 设为默认 + 全量回归 | `verify` **PASS 12**；CM/MHz ≥ **2.69** | 一行改回 |
| **S1** | 7 级**单发射**（只拆流水，不加宽） | 功能全过；**fmax ≥ 130**；CM/MHz 不降 | 保留 5 级 |
| **S2** | 加 E2 的第二个 ALU + "猜后验证"（仍单发射） | 功能全过；**停顿 ≤ 45,000**；CM/MHz ≥ **3.0** | 关掉 E2，退回 S1 |
| **S3** | 加宽到双发射（slot1 仅 ALU） | 功能全过；**IPC ≥ 0.95**；CM/MHz ≥ **3.4** | 关 slot1 |
| **S4** | 放开 slot1 的 BR/MUL | **CM/MHz ≥ 3.8**；fmax ≥ 100 | 收回 slot1 限制 |
| **S5** | `-O3`（imem 24 KB）+ 预测精度 95% | **CM/MHz ≥ 4.1**；LUT ≤ 6,000 | 回 `-O2` |

**S1 和 S2 是两个独立的探针**，价值极高：
- S1 如果 fmax 上不到 130，说明"7 级拆分"本身不干净，先修 S1 再谈别的；
- S2 如果不加宽就能到 3.0，说明"猜后验证"这条最难的机制已经跑通，后面加宽是加法。

## 9. 性能估计（保守 / 中位 / 乐观）

| 阶段 | CM/MHz 保守 | 中位 | fmax 保守 | 中位 | 绝对吞吐 保守 |
|---|---:|---:|---:|---:|---:|
| 现状 `-Os` | 2.16 | — | 150 | — | 324 |
| **S0 `-O2`（已实测）** | **2.69** | — | 150 | — | **404** |
| S1 7 级单发射 | 2.69 | 2.75 | 130 | 140 | 350 |
| S2 猜后验证 | 3.00 | 3.15 | 120 | 135 | 360 |
| S3 双发射（slot1=ALU） | 3.40 | 3.55 | 105 | 120 | 357 |
| S4 放开 BR/MUL | 3.80 | 4.00 | 100 | 115 | 380 |
| **S5 + `-O3` + 精度 95%** | **4.10** | **4.40** | **95** | 110 | **390** |

**必须直说的**：即使走到 S5，**绝对吞吐 390 仍略低于 `-O2` 单发射的 404**。
CM/MHz 达标（4.1）但整体没变快 —— 这是双发射的固有代价，不是实现不好。

> 这也是为什么我在 `CM42-ROUTES.md` §7.6 坚持要先确认评审口径：
> **如果赛题只看 CM/MHz，这条路值得走；如果看绝对吞吐，`-O2` + 单发射极限（3.4 @ 145 = 493）
> 才是最优解，而且风险低 3 倍。**

## 10. 风险登记

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| **R1** | **E1 在操作数不齐时产生副作用**（写寄存器/触发异常/更新 BTB） | 中 | **正确性错误，最难查** | E1 的所有副作用统一由 `opnd_ready` 门控；仿真加"E1 无效时副作用必须全 0"的断言 |
| R2 | 依赖检查成为新 top-1 | 高 | fmax 卡住 | 预译码前瞻（F2 算 rs）；必要时 D 拆成 D1/D2（8 级） |
| R3 | E2 重定向路径过长 | 高 | 5 拍惩罚变成 6 拍 | 重定向信号在 E2 前半段就算出，末段只做 mux |
| R4 | imem 24 KB 的布线代价吃掉收益 | 高 | −5~10 MHz | 与流水重构同批做；Pblock 对齐 BRAM 列 |
| R5 | LUT 超 6,000，`CoreMark/LUTs` 恶化 | 中 | 输一项指标 | 4 ALU + regfile 预算见 §5；超了就砍 slot1 的功能 |
| R6 | 分支预测精度上不去（<93%） | 中 | 误判惩罚放大 3.57 倍，收益反转 | **S2 之前必须先做精度提升**，否则不要上 S2 |

**R6 是 go/no-go 的隐藏门槛**：本方案把"停顿"换成了"惩罚"，**它是押注预测精度的**。
如果精度停在 92%，`8,020 × 3.57 = 28,631` 的额外惩罚会吃掉 load-use 收益的一半。

## 11. 与既有工作的关系（不要重复造）
