# 网络、存储与控制接口

## 数据通路

```text
OV7670 DVP18 -> camera_dvp_capture -> RGB565 双缓冲 -> LCD 连续扫描
                                   |
                                   +-> 64x64 灰度/肤色轮廓快照 -> 双模型ROM / INT8 卷积引擎
                                                           |
原 MES50HP RV32IM 内核 <- MMIO 结果 RAM <--------------------+
          |
          +-> 数字分类 / 质量门限 / 三次一致 / 工单核对 / 去重计数
          +-> 检测框与业务状态 -> LCD帧边界统一更新 -> 红框、标签、MATCH/WRONG
```

推理时不会等待 LCD 停止扫描，也不暂停摄像头采集。卷积忙或结果待 CPU 确认时丢弃后续识别快照；读取结果期间存储器保持稳定。摄像头和 LCD 的原双缓冲交换继续运行。

相机MCLK为12.5 MHz，采集器在50 MHz域同步PCLK、HREF、VSYNC和数据，检测PCLK上升沿后按高字节、低字节组装RGB565。CLKRC为03以降低初始相机速度；实际PCLK仍需板上测量。只接受320×240完整帧并抽样为160×120，短行、奇数字节、溢出或像素总数不符会被拒绝。显示确认前停止写入缓冲区。原始P/L/V计数与有效帧F分开显示，诊断和18针映射见 `CAMERA_DEBUG.md`。

从 160×120 采集帧取中央 x=16…143 的 128×120 区域，上下各补 4 个源像素行，隔行隔列抽样为 64×64。RGB565 先按高位复制扩展到 RGB888，再取 `(R + 2G + B) >> 2`，反相并右移一位得到 0…127。快照的上下各两行固定为 0。首版数字模型因此适用于浅底深色笔画。

手势模式保持相同裁剪与采样，改为RGB565展开后的肤色轮廓：`R>50 && G>25 && B>10 && R>G+5 && R>B+15` 输出127，否则0；补零区仍为0。固定阈值对肤色、光照和背景敏感，肤色相似的背景可能产生误检。此预处理与手势训练逐像素一致，数字模型预处理不变。

## 固定拓扑

所有卷积为零补边，隐藏层使用 ReLU 和 0…127 饱和。输入与隐藏激活的单位均为 1/128；权重量化为有符号 INT8，每层使用独立的二次幂比例。偏置为 INT32，累加后做有符号右移。输出层不做 ReLU，保留有符号分数供 CPU 解码。

| 层 | 输入 | 卷积 / 步幅 | 输出 | 权重字节 | 权重偏移 / 偏置偏移 |
|---|---|---|---|---:|---|
| 0 | 64×64×1 | 3×3 / 2 | 32×32×8 | 72 | 0 / 0 |
| 1 | 32×32×8 | 3×3 / 2 | 16×16×16 | 1152 | 72 / 8 |
| 2 | 16×16×16 | 3×3 / 2 | 8×8×24 | 3456 | 1224 / 24 |
| 3 | 8×8×24 | 3×3 / 2 | 4×4×32 | 6912 | 4680 / 48 |
| 4 | 4×4×32 | 3×3 / 1 | 4×4×32 | 9216 | 11592 / 80 |
| 5 | 4×4×32 | 1×1 / 1 | 4×4×27 | 864 | 20808 / 112 |

权重共 21672 字节，139 个偏置共 556 字节。权重文件按 `[输出通道][核行][核列][输入通道]` 排列，激活及结果按 `[行][列][通道]` 排列。每个 4×4 单元的 27 个数依次是：目标分数、中心 x/y 的单元内偏移、全图相对宽高、22 个类别分数。回归坐标使用 Q7。

模型bank0只启用数字类别12…21，bank1只启用手势类别3…11。两组分别为数字0～9和手势1～9；构建器校验类别、结构及每个权重哈希。CPU在全图最高目标分数单元中独立选择当前模式的类别，再与工单期望数字比较。两模型当前均采用目标分数>=72、前两类分数差>=24才作为有效观察；分数<40作为空场，中间区间不作为空场。没有多框NMS，场景要求一次一个目标。模型坐标到LCD为 `x=112+4*x_model`、`y=8+4*y_model`，然后裁剪到摄像头显示区域。

NPU在接受start时锁存bank号，忙期间改变外部选择不会混用权重。SoC的模式写入同时复位NPU与快照、清除旧检测框和待提交包；固件重置连续确认，重新清场。两个模型共用激活RAM与计算单元，不同时推理，单次均为1769238周期（50 MHz下约35.38 ms）。

业务状态机在 `firmware/numeric_guard.h`，活动固件为 `firmware/numeric_main.c`，历史 `main.c` 不参与构建。上电/切工单/故障后先要求三次空场，随后三次相同数字且中心偏移每次不超过12模型像素才记录事件；锁存后只能通过三次空场解锁。拒识不会代替空场解锁。冻结、彩条、停止推理、相机异常或一秒无新结果会取消当前确认并要求重新清场。

## 资源判断

所提供 EBF HDMI 工程的 `20_hdmi_colorbar/pds_prj/device_map/run.log` 列出此目标器件有 66600 LUT、133200 FF、240 APM 和 155 DRM。它是参考工程报告，不是新识别工程的资源使用报告。

本设计使用单个顺序 INT8 MAC 数据通路，每个乘加包含同步存储器读取和累加两个周期。存储按固定数组留量：双模型ROM64 KiB（每组补齐32 KiB）、激活双区16 KiB、结果2 KiB、双模型偏置2 KiB、移位12字节、字库1 KiB、可追溯输入副本4 KiB；另有RISC-V的16 KiB指令和16 KiB数据存储及预测表。视频双缓冲逻辑像素数据为76800字节，实际映射可能按RAM深度和宽度增加容量，例如推导为65536×16。手势新增的固定ROM容量为32 KiB权重、1 KiB偏置及6个移位字节。

当前DVP18版本的PG2L100H映射资源和布局布线时序见 `BOARD_VALIDATION.md` 及对应原始报告；旧FIFO版本的资源不能当作本版测量。更大输入、更多通道、并行MAC或外部存储需重新设计并测量资源与时序。

## MMIO

基址 `0xA1000000`，32 位对齐访问。CPU 沿用原 16 KiB IMEM / DMEM 映射，固件为 RV32IM。构建直接使用已转换的Verilog处理器源码；没有修改原 50K 工程，也没有把原 HDMI、EEPROM 和密码门禁外设加到新顶层。

| 偏移 | 内容 |
|---|---|
| 00 | ID `0x56530101` |
| 04 | 状态位 0 配置成功、1 配置失败、2 图像有效、3 NPU 忙、4 NPU 完成、5 启用推理、6 冻结、7 彩条 |
| 08 | 摄像头帧计数 |
| 0C | 最近一次 NPU 周期 |
| 10 / 14 | 结果索引 / 同步读出的 INT32 结果；索引写入后固件插入两个 NOP 再读 |
| 18 | 控制位 0 启用、1 冻结、2 彩条、3 单次摄像头重配、4 单次结果确认 |
| 1C | 50 MHz 自由运行的 32 位周期计数，固件用无符号差处理回绕 |
| 20 / 24 | 待提交左上 / 右下坐标，低 16 位 x，高 16 位 y |
| 28 | 待提交标签，位 31 有效，位 5…0 类别，位 14…8 目标分数 |
| 2C | 请求在下一 LCD 帧边界提交全部检测信息 |
| 30 | CPU 已确认的推理计数 |
| 34 | 待提交业务面板：状态[2:0]，期望[7:4]，当前数字[11:8]（15为空），连续确认[13:12]，可核验[15]，Q7分数[22:16]，手势模式[23] |
| 38 / 3C | 待提交OK / BAD完整32位计数 |
| 40 | SW4下一工单事件，读取清除；多个未处理按键合并为一个事件 |
| 44 | 当前推理启动时的32位周期时间戳 |
| 48 | 自由运行周期计数器高32位；CoreMark采用高-低-高重读保证一致 |
| 50 | CoreMark测试完成标志，普通核验固件不写 |
| 54 / 58 | 4096字节输入副本的索引 / 同步读出的Q7数据，写索引后两个NOP再读 |
| 5C | 模型选择，位0：0标签、1手势；写入取消当前推理、快照和旧显示提交 |
| 60 | SW4长按模式切换事件，读取清除；长按不产生40短按事件 |
| 80 / 84 | UART 发送字节 / 发送忙 |
| 88 / 8C | UART 接收字节（读后清有效）/ 接收有效与错误计数 |

索引2C写入时先将整组框、类别、面板和计数锁存成一份完整提交包，再在LCD帧边界更新；CPU预写下一包不会撕裂上一包。禁用、彩条、相机失效时立即隐藏框，冻结时保留画面但暂停核验。持续一秒未获得新结果时固件清除旧框。新框和当前视频来自不同时间的帧，快速运动时会存在位置延迟。

## 事件与输入追溯

事件格式为 `EVENT,sequence,timestamp,expected,digit,status,object_score,class_margin,passed,rejected,npu_cycles,decision_cycles,mode`，所有数值字段均为8位十六进制。mode为0标签、1手势，digit统一表示人读的数字，手势为1～9。状态2为MATCH，3为WRONG。timestamp是50 MHz的低32位，约85.9秒回绕；长时间日志需结合主机时间、启动标志和序号，不直接当绝对时间。decision_cycles从NPU启动算到CPU判定完成，包含NPU计算，不包含之前的采集和之后的LCD提交。两模式共用passed/rejected/sequence计数，可按mode过滤日志统计；切换模式只清确认状态，q命令清OK/BAD。

维护命令d在完整推理完成、尚未确认结果时回读输入副本，此时快照不会被后续帧覆盖。输出BEGIN、64行各64字节的十六进制数据、END与标准CRC32。CRC32覆盖实际4096字节Q7输入。LCD预览独立，模型计算与数字判定仍在板上完成；电脑只接收维护数据与审计结果。
