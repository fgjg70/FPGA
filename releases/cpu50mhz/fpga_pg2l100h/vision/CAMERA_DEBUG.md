# 18针DVP摄像头上板诊断

2026-11-02的实物照片确认：当前蓝色OV7670模块是18针DVP接口，带PCLK、MCLK、RESET和PWDN。此前依据资料中的22针AL422模块编写的FIFO采集及转接表不适用于此实物。当前J11应用已改为DVP采集；旧22针接线说明停用。

CPU、NPU、采集保持50 MHz，视频27 MHz，LCD像素9 MHz；摄像头接J7，AN430接J11。FPGA输出12.5 MHz MCLK，PWDN固定为低，MCLK启动1 ms后释放RESET，再等待50 ms开始50 kHz SCCB配置。CLKRC设置为03，先降低相机速度完成链路调试。手势和数字标签权重保持原样。128位诊断信息随272位完整数据包在视频帧边界更新。

## 屏幕状态

| 顶部文字 | 含义 |
|---|---|
| CAM WAIT，黄色 | 摄像头配置尚未完成 |
| CAM ERR，红色 | SCCB 事务失败，或读回的 PID/版本与 OV7670 不符 |
| NO FRAME，黄色 | 摄像头配置和 ID 检查通过，尚无可显示的完整图像帧 |
| READY、WAIT、MATCH 等 | 摄像头配置、完整图像帧已有；继续核对画面和识别流程 |

左侧显示下列数值，全部采用十六进制。请提供一张能看清这些文字的屏幕照片，或记录每一项的值。

| 字段 | 含义 |
|---|---|
| ID | PID 寄存器读回值，成功时应为 76 |
| VR | 版本寄存器读回值，当前工程要求 73 |
| ST | 配置寄存器序号，00 是首次软复位写入，31 是最后一项；读取 ID/版本期间保持 31 |
| RX | 位7为同步PCLK，位6为同步HREF，位5为SCL，位4为同步SDA，低四位为DVP采集状态 |
| V | VSYNC 输入同步后的原始上升沿计数，尚未配置成功时也会统计；没有脉宽或帧周期有效性检查 |
| F | 已采集的完整帧计数 |
| T | 帧等待超时次数，仅配置成功并启动采集后有效 |
| P | PCLK输入同步后的原始上升沿计数，16位循环计数 |
| L | HREF输入同步后的原始上升沿计数，16位循环计数 |
| B | 被拒绝的帧计数，例如行宽、行数、字节数或总像素数不符 |
| C / E | 配置成功 / 配置失败标志，正常为 C1 E0 |

`C0 E1 ST00 ID00 VR00` 表示第一次写入即失败，优先检查供电、SCL/SDA、RESET/PWDN 和转接线。这里的 ID00 可能只是尚未读取 ID 的初值，不能据此认定传感器的实际 ID 是零。

`ID76 VR73 C1 E0` 后，先检查P、L、V是否持续变化，再看F。F只接受320像素×240行、每像素两字节的完整帧，隔行隔列存为160×120。短帧、空帧、奇数字节和多余像素会被拒绝。若B增长而F为零，需核对相机输出格式、PCLK速度及数据/同步线；若P不变，优先检查MCLK、PWDN、RESET与PCLK。F增长后仍须目视确认实际画面和串口快照内容。

RX低四位0表示等待帧，1表示采集，2表示等待LCD交换确认。高四位电平会随输入变化；空闲高电平不证明摄像头有应答。配置失败时底部应显示以DVP18开头的检查提示，可据此区别旧FIFO位流。

用户随后提供的实拍确认顶部为CAM ERR，ID00、VR00、ST00、RX30、F0000、T0000、C0 E1，并报告触碰摄像头接线时V增加。当前故障已定位到第一项寄存器0x12写入0x80时的总线错误；尚未执行ID/版本读取，不能把初值00当成传感器实际ID。现有诊断没有记录错误发生在设备地址、寄存器地址还是数据字节。

旧版把实际SCL脚W18当作VSYNC，触碰后V增加不能证明相机输出了帧。旧版还未向实物MCLK脚T17提供时钟，并把实际PWDN脚Y25作为高电平FIFO控制。这些接口映射错误现已修正；接触质量和模块状态仍需新位流的实物反馈确认。T在配置失败时保持零属于当前逻辑。

## 优先核对的接线

当前约束按照片中的18针摄像头与J7逐号对应编写：1接1、2接2，依次到18。此处依赖实际连接没有另加交叉转接；如存在转接板或飞线，必须按导通关系修订，不能只看同名丝印。以3.3V方焊盘为1号，另一列同排为2号；背面观察时左右镜像。J7-2才是GND，旧文档中的J7-6 GND、J7-2 SCL写法有误。

| J7 / 摄像头针号 | FPGA球位 | 当前信号 |
|---|---|---|
| 1 / 2 | 电源 | 3.3 V / GND |
| 3 / 4 | W18 / Y23 | SCL / SDA |
| 5 / 6 | V16 / V18 | VS / HS(HREF) |
| 7 / 8 | V17 / T17 | PCLK输入 / MCLK输出 |
| 9 / 10 | U19 / T18 | D7 / D6 |
| 11 / 12 | T19 / U20 | D5 / D4 |
| 13 / 14 | V21 / T20 | D3 / D2 |
| 15 / 16 | U21 / Y22 | D1 / D0 |
| 17 / 18 | AA25 / Y25 | RESET输出 / PWDN输出 |

这是按实物信号顺序重映射后的约束，底板原网名不代表当前逻辑信号。例如底板CMOS_D0的T17现输出MCLK，底板CMOS_RESET的V17现输入PCLK。完整表位于 `build/j11/WIRING.md`，原理图依据为 `ebf_pg2l100h_demo/EBF_PG2L100H676_BASEBOARD_SCH.pdf` 第7页。

实物17、18号分别为RESET、PWDN，15、16号是数据线D1、D0；不要套用旧22针模块的RESET/PWDN针号。需要调整连接时先断电，随后重新下载当前RAM位流。

## 画面方向

2026-11-02用户实拍确认DVP版已有真实摄像头图像，ID76、VR73、C1 E0，完整帧计数非零；画面为倒置。当前J11应用通过传感器MVFP寄存器0x1E同时启用水平镜像和垂直翻转，将配置值由07改为37，完成180度旋转。`camera_config.v` 提供可选SENSOR_MVFP参数，J11顶层显式设为37。

旋转发生在传感器输出端，因此LCD预览、RGB565快照和手势/标签模型输入采用同一方向。当前模式仍按顺序输出像素，无需改动帧缓冲地址或检测框映射。修正后是否正立以重新下载后的实物画面为准。

## 重试和手势测试

按 SW2 重新启动摄像头配置。SW3 是 FPGA_CONFIG_N，不用于本次逻辑复位；按下会清除当前配置，需重新下载。

相机画面正常后，长按 SW4 至少一秒切换到 `HANDTEST`，再测试一至九手势。上电默认 `NUMGUARD` 数字标签模式，短按 SW4 仅切换期望数字。手势模型仍是实验版本，公开验证集 148 个正样本中仅 52 个被正确接受；相机恢复后仍需采集当前摄像头的独立样本验证和改进。

串口联调需另接开发板 CH340 的 USB 接口，并接通 J9 的 1-2、3-4。COM12/COM13 属于 FTDI 下载器，不能当作已验证的应用串口。应用串口为 115200、8N1；确认出现 `NUMGUARD S=` 状态行后，`g` 切手势，`l` 切标签，`?` 查询状态，`d` 获取实际模型输入快照。

此前DVP采集版本已完成全部13项回归，包括严格Verilog-2005、异步PCLK字节采样、RGB565字节序、完整帧检查、噪声/短帧/奇数字节拒绝、冻结、超时、LCD、272位跨时钟一致性、实际Pango GPLL板级MCLK/复位及双模型固件。本次旋转仅修改传感器配置参数，执行严格Verilog-2005和板级仿真两项检查。实际构建、下载和实物验收记录在 `BOARD_VALIDATION.md`，此前完整回归保存在对应冻结证据目录，软件仿真图不能代替板卡画面。
